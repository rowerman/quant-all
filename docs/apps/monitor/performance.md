# 因子评估性能与资源基线

## P0-01 算子优化固定基线（2026-10-27）

本轮为后续相关性算法优化、Numba 验证和 C++ 批量核固定当前 Python 基线。证据位于
`AiRecord/benchmarks/V105/p0-01-20261027/`，包含环境、302 个输入文件 SHA-256、不可变
案例参数、稳定金标准、逐事件耗时、独立进程峰值 RSS 和 manifest。

当前环境为 Python 3.12.3、DuckDB 1.5.5、NumPy 2.2.6、pandas 2.3.3、SciPy 1.18.1，
4 CPU、约 16GB 内存。数据版本为 `tushare_fullA_20000104_20261015`；行情主库为 17,999,882
行，日历 2000-01-04～2026-10-15 共 6,488 日；
正式因子目录为 297 个 Parquet、约 1.8GB。输入树 SHA-256 为
`543bb728c7c279fc3c460a67d9c1e0a538a625d743b88debb2401d73da323865`。

| 固定案例 | 参数摘要 | 耗时 | 峰值 RSS |
|---|---|---:|---:|
| 完整评估 | MOM_20、2023-10-15～2026-10-15、全 A、5 日 close、10 组 | 293.4s | 3152.9MB |
| 相关性单 stage | 同完整评估口径，`top_n=10` | 234.2s | 3410.3MB |
| 全历史轻量 IC | MOM_20、2000-01-04～2026-10-15 | 12.8s | 1395.5MB |
| 单族单年构建 | momentum、2024 全年、临时目录 | 11.8s | 3506.9MB |
| 挖掘技术门禁+快速筛选 | `mean(close,5)`、2024-05-06～2024-06-28 | 13.6s | 1156.0MB |

完整评估中相关性为 236.0 秒，是最明确的热点；面板构建后主要其他 stage 为 2.1～18.0 秒。
完整评估与单 stage 的相关性 payload 在 `1e-10` 容差内一致。稳定金标准使用
`operator_baseline_v1`：日期、名称、顺序、有效计数和排名结果要求完全一致；浮点统计默认
使用 `abs=1e-10, rel=1e-10`。公共接口中的 NaN/inf 仍为 `null`，底层边界案例使用
`__NaN__`、`__+Inf__`、`__-Inf__` 明确区分。
后续核函数微基准至少运行 3 次并取中位数，不能替代上述真实 stage 端到端比较。

复现命令：

```bash
.venv/bin/python -m tools.monitor.operator_baseline --suite all
```

完整评估只运行一次；边界案例重复执行并要求完全一致。每个案例使用独立子进程测量峰值
RSS，避免前一案例的 Python/DuckDB 内存污染后续结果。本轮没有接入 C++，也未修改业务
计算逻辑。

## P0-02 候选相关性目标行裁剪（2026-10-27）

审计确认正式因子页面的热力图读取完整 `matrix` 与 `days`，因此正式路径继续保留全部
因子对。非正式挖掘候选只消费目标因子与正式因子的关系，原先却复用了完整矩阵累计，
产生了不参与展示的正式因子两两相关。

P0-02 将非正式候选切换到目标行计算，并让两条路径共用缺失掩码、稳定排序、并列平均名次
和相关计算。47 个相关性列时，候选结果由 2,209 个有限矩阵单元格降为 93 个目标行/列
单元格。固定三年案例使用现有 Parquet 构造 `formal=False` 视图，结果如下：

| 路径 | 相关性阶段 | 案例总耗时 | 峰值 RSS | 结果对照 |
|---|---:|---:|---:|---|
| 优化前候选完整矩阵 | 233.5s | 240.1s | 2788.2MB | 基准 |
| 优化后候选目标行 | 132.9s | 140.0s | 2682.3MB | 目标行最大差异 2.22e-16，有效日和 Top-N 顺序一致 |
| 正式完整矩阵复测 | 228.6s | 235.1s | 2681.7MB | 与 P0-01 金标准完全一致 |

候选相关性阶段下降 43.1%，峰值 RSS 下降 3.8%。正式完整矩阵没有裁剪，耗时保持原量级。
证据位于 `AiRecord/benchmarks/V106/p0-02-20261027/`。本轮是 Python 算法优化，没有真实
采用 C++，因此不增加 C++ 模块收益记录。

## P0-03 逐日排名和缺失掩码缓存（2026-10-27）

单月剖析显示正式 2026 年 8 月每个交易日约 5,221 只股票、47 个因子、20 个缺失掩码组和
205 个组对，需要约 890 次“因子×成对样本”排名；原排名缓存命中率约 4.2%。热点集中在
排名构造、中心化和范数计算，而不是 DuckDB 月块取数。

本轮为每个交易日建立私有工作区，按打包字节复用有限值掩码和组对交集，使用因子优先连续
布局和稳定排序索引，预分配排名矩阵，并由并列块大小直接计算范数。成对交集仍在实际样本
内重新排名，缓存不跨日或跨请求。

| 案例 | 修改前 | 修改后 | 变化 |
|---|---:|---:|---:|
| 单日 5,219×47 矩阵，5 次中位 | 0.1976s | 0.1666s | 下降 15.7% |
| 三年正式相关性 stage | 228.6s | 209.1s | 下降 8.5% |
| 三年单 stage 峰值 RSS | 2681.7MB | 2680.0MB | 下降 0.1% |
| 三年候选目标行 stage | 132.9s | 127.8s | 下降 3.8% |

单日修改前后矩阵最大差异为 0，`NaN` 位置完全一致；三年相关性金标准与 V105、V106 均在
约定容差内一致。候选目标行峰值 RSS 为 2826.1MB，是 V106 基线的 1.054 倍，未超过
1.2 倍门槛。证据位于 `AiRecord/benchmarks/V107/p0-03-20261027/`。本轮仍是 Python
算法优化，没有真实采用 C++，因此不增加 C++ 模块收益记录。

## P0-06 因子族全历史一次计算（2026-10-27）

原构建器按“族 × 年”执行查询，每个年度都从主库开头扫描到该年末。新路径对每个族只执行
一次截止到区间末的查询，由 DuckDB 按年分区，再校验年度文件并原子发布。`yearly` 模式
保留为回退路径。

| 案例 | SQL 数 | 输入有效交易行 | 耗时 | 峰值 RSS |
|---|---:|---:|---:|---:|
| 动量 2023～2024 逐年 | 2 | 28,846,271 | 22.303s | 3491.6MB |
| 动量 2023～2024 一次计算 | 1 | 15,069,961 | 13.140s | 3236.6MB |
| 动量 2000～2026 一次计算 | 1 | 17,413,423 | 34.672s | 3508.8MB |

两年案例墙钟下降 41.1%，输入扫描量下降 47.8%，峰值 RSS 为原路径的 0.927 倍。全历史
案例生成 27 个年度文件、17,999,882 行、约 323.3MB；相对旧的 27 次累计扫描
173,510,525 行，扫描量下降 90.0%，峰值 RSS 与 P0-01 单族单年基线 3506.9MB 基本持平。
新路径与逐年路径的 2023、2024 文件主键、空值和全部因子值逐行一致；跨年窗口、停牌行、
前视样例、财务 ASOF、目录刷新和故障回滚定向测试通过。

全族 2024 年回退验证构建了 11 族、47 个因子、14,264,745 个主键行，耗时 191.6 秒，
峰值 RSS 3330.7MB。全历史路径默认将 DuckDB 缓冲上限设为 3GB，临时溢出不写入正式因子
目录；可通过 `QUANT_FACTOR_BUILD_MEMORY_LIMIT` 覆盖。

证据位于 `AiRecord/benchmarks/V110/p0-06-20261027/`。本轮采用 Python 编排和 DuckDB
查询计划优化，没有采用 C++，不计入 C++ 模块替换收益。

## P1-01 批量核契约与逐日排名门禁（2026-10-27 V112）

本轮新增统一 `kernels.NativeKernelBackend` 契约、Python 回退、输入校验和 Numba 研究
原型。Numba 没有接入评估默认路径。P1-01 按用户确认的逐日排名门禁验收；Spearman
Numba 只保留诊断证据，真实 stage 收益留给 P1-02 的 C++ POC 验证。

固定真实截面为 2026-08-03、5,219 只池内股票和 47 个正式因子；排名使用 2026-08 的
21 个交易日、109,652 行。每个内核运行 5 次取中位数，Numba 冷启动在独立缓存目录测量。

| 内核 | Python 热运行中位 | Numba 热运行中位 | 加速 | Numba 冷启动 |
|---|---:|---:|---:|---:|
| Spearman 5,219×47 | 0.1532s | 0.8576s | 0.179x | 19.798s |
| 逐日排名 21 组 | 0.0170s | 0.0084s | 2.023x | 0.563s |

Spearman 结果与当前 Python 实现在 `1e-10` 容差内一致，有效计数完全一致；排名与 pandas
和当前 NumPy 实现逐值一致。逐日排名达到 `1.5x` 门禁，因此 P1-01 通过；Spearman
仅 `0.179x`，继续明确标记为未达标，不作为 C++ 收益证据。

V111 的历史 Spearman 门禁失败记录仍保留在
`AiRecord/benchmarks/V111/p1-01-20261027/`。V112 排名门禁证据位于
`AiRecord/benchmarks/V112/p1-01-20261027-recheck/`。本轮实际 C++ 替换模块数为 0，
不计入 C++ 模块替换收益。

## P1-02 C++ Spearman 单核 POC（2026-10-27）

本轮用 C++20、pybind11 和 CMake 实现 `quant_native.pairwise_spearman`。Python 与 C++
在独立子进程读取同一个固定 2026-08-03 截面，矩阵为 5,219×47、单组、单线程，各自完成
一次首次调用和 5 次热运行。峰值 RSS 由子进程内后台采样 `/proc/self/statm`，避免继承
父进程的 `ru_maxrss`。

| 后端 | 热运行中位 | 峰值 RSS | RSS 增量 |
|---|---:|---:|---:|
| Python | 0.172836s | 282.820MB | 48.305MB |
| C++ | 0.073312s | 283.129MB | 48.570MB |

C++ 加速 `2.358x`，峰值 RSS 为 Python 的 `1.001x`。相关系数在 `1e-10` 内一致，有效
计数完全一致。输入树 SHA-256 仍为
`543bb728c7c279fc3c460a67d9c1e0a538a625d743b88debb2401d73da323865`。

本轮没有修改评估业务调用路径，默认后端仍为 Python，实际 C++ 替换模块数为 0。证据位于
`AiRecord/benchmarks/V113/p1-02-20261027/`。

## P1-03 Spearman 接入评估相关性（2026-10-27）

P1-03 把完整矩阵和目标行 Spearman 都接入统一 `kernels` 后端。候选路径新增 C++ 目标行
模式，只计算目标行、目标列和对角线，避免按现有全矩阵核重算不需要的因子对。生产默认
切换为 `auto`：扩展可用时 native，不可导入时 Python；运行期原生错误不静默回退。

固定三年区间、全 A、MOM_20、单线程、V105 输入哈希不变：

| 范围 | Python | native | auto | native RSS比例 |
|---|---:|---:|---:|---:|
| 正式完整矩阵 | 217.770s | 140.460s | 135.788s | 1.0001x |
| 候选目标行 | 137.599s | 118.680s | 120.995s | 1.0001x |

正式 native stage 下降 `35.5%`，auto 下降 `37.6%`；候选 native 加速 `1.159x`，auto
加速 `1.137x`。固定 5,219×47 截面核微基准为完整矩阵 `0.167855s → 0.060035s`
（`2.796x`）、目标行 `0.042791s → 0.021802s`（`1.963x`）。相关系数在 `1e-10` 内
一致，有效计数、日期、名称、Top-N 顺序和 `NaN` 位置一致。证据位于
`AiRecord/benchmarks/V114/p1-03-20261027/`。

本轮把“评估相关性 Spearman”登记为第 1 个实际 C++ 替换模块。这里只计入相关性完整矩阵和
候选目标行，不把尚未接入的排名、Pearson、MAD、OLS 或其他评估 stage 算作收益。

## V11 资源实测与并发验收（2026-10-13 复测）

环境：4 CPU、约16GB内存、DuckDB1.5.5，已有本地行情与29因子产物。
benchmark在独立子进程顺序运行，RSS为该进程峰值，包含Python/NumPy/Pandas与DuckDB，
工作内存上限不是RSS硬上限。事件字节统计JSON载荷，不含HTTP/SSE字段与浏览器画布。

### 单进程基准（阶段隔离版本，2026-10-13 20:22 完成）

| 案例 | 时间 | 峰值RSS | 事件载荷 |
|---|---:|---:|---:|
| 默认最近3年完整分析/MOM_20/全A/5日close/10组 | 176.6s | 3157MB | 560KB |
| 全历史轻量IC/2000-01-04～2026-09-28 | 17.4s | 1309MB | 695KB |
| 2021-01-01～2026-09-28完整分析（接近行数保护） | 353.2s | 5381MB | 1023KB |
| 四因子默认完整对比 | 724.7s | 3441MB | 2205KB |
| 双任务并发（benchmark concurrent，两线程直接调用service.run） | 352.0/352.1s | 4734MB | 各约550KB |
| 超限预检 | 拒绝 | 149MB | EVAL-101/EVAL-102 |

单任务数值与2026-10-12的175.0s/3095MB基本一致，无回退。轻量IC的本轮绝对值
（17.4s，另测16.5/15.9/16.1s）高于2026-10-12记录的13.77s，属环境漂移：加锁与
不加锁各跑2次分别为15.98/15.39秒与15.98/16.49秒，隔离本身对该路径无影响。
2021～2026近上限与4因子完整对比依旧通过，未触碰2400交易日与800万行保护。

### 并发稳定性验收（2026-10-13）

验收入口 `tools/monitor/stress.py`：本地模式进程内走真实Scheduler与SSE，
HTTP模式对真实uvicorn发两路SSE。原始记录 AiRecord/benchmarks/V11/20261013-stress-*.jsonl。

| 场景 | 结果 |
|---|---|
| 双任务完整分析重复5轮（本地，真实调度器+SSE） | 497.9/439.8/348.9/375.8/387.8秒，峰值RSS 4753.5~5038.1MB，两路每次都收到完整16个事件，退出码0，无SIGSEGV |
| 双任务完整分析1轮（真实HTTP） | 371.9秒，服务峰值RSS 4592.9MB，两路均done |
| 取消（真实HTTP，读到第二阶段后断连） | 5.0秒后调度器日志出现 `released cancelled=True`，同伴请求正常done，随后light IC探测仍200 |
| 慢消费者（真实HTTP，1.0秒/事件读） | 慢请求停在4/16事件时，light IC请求12.1秒完成、`/api/factors`0.889秒返回200，慢请求最终拿到全部16个事件 |

隔离代价：原生阶段互斥，两个完整分析互相等待，并发总时长约为单任务的2倍
（352秒对176.6秒），但内存不翻倍（4.7GB对单任务3.2GB）。背压等待与事件交付不持锁，
预检名额在计算前占用，队列满返回429。

原生根因仍未知：本轮gdb取证未捕获到SIGSEGV原生栈（见changes/20261013-2.md）。
阶段隔离只覆盖后端入口，直接并行调用底层calculate函数不在保护范围内。
历史双任务SIGSEGV证据保留在AiRecord/benchmarks/V11（concurrent-capped-crash.log等）。

相关性最初默认三年177s/RSS约4GB（仅面板+相关性），
P9优化后默认完整分析176.6s，其中相关性约116s，完整RSS约3.2GB。
优化按相同缺失掩码分组、每列一次排序后在成对交集重新计算并列名次，结果对照scipy。
只读连接默认1GB工作内存、2个DuckDB线程，轻量IC单独4线程。

完整分析保留2400交易日和800万行保护。行数采用涉及年份的parquet元数据上界，
2020～2026年上界8069254行被拒绝；全历史6480日被拒绝。
轻量IC通过≤15s不能说明分位、风格、相关性也能全历史运行。
同请求4因子顺序释放前一上下文，相关性每个因子独立计算，不在请求间缓存。
队列满429、事件队列2条背压、排队取消、运行阶段边界释放由后端测试验证。

原始JSON与测试记录：AiRecord/benchmarks/V11。启动参数、错误语义见api.md。
