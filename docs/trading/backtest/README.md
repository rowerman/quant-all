# 回测模块

## 定位

`trading/backtest/` 是 A 股日频回测执行层。V48 起正式记账由 `ledger.py` 的原始价账本负责，
处理现金分红、送转/拆并、配股、应收分红、零头折现和 FIFO 红利税；VectorBT 只保留为
历史口径对照与依赖版本记录。

| 模块 | 职责 | 修改注意事项 |
|---|---|---|
| `specs` | 策略配置、回测参数与配置哈希 | 字段增删会改变 `config_hash`，历史版本必须仍能反序列化 |
| `config`/`logging_conf` | 路径常量、资源上限、按模块分目录的日志 | 上限改小前先看本页的实测内存 |
| `universe` | 全 A 池与指数成分池；成分并集取数 | 成分口径直接复用 `calculate.universe`，不要在这里另立一套 |
| `data` | 行情/因子/基准/公司行动取数与 `MarketData` 契约 | 逐字段读、`float32`；执行价格走原始口径，别再合并成全字段长表 |
| `signals` | 因子打分、股票池过滤、调仓日与目标权重；按策略类型路由到提供者 | 权重矩阵用 NaN=不动、0=清仓；提供者返回只允许正权重且单行合计不超过 1 |
| `providers`/`provider_schema`/`strategies` | 目标权重提供者注册、发现、参数结构、参数/版本校验和源码哈希 | `trading/backtest/strategies/*.py` 模块导入时注册；页面参数结构在 `_param_schema.py` 维护；导入失败、重复来源和版本不匹配必须带模块名报错 |
| `risk` | 单股权重上限与含现金单边换手约束 | 换手约束按每轮真实持仓重算，不能在最终订单层截断 |
| `orders` | 持仓状态机判方向、规则拒单、被拦交易与现金缩水的每日重试、退市整理期退出与核销 | 被拦下的交易必须能重试，不能丢状态；费用由账本按统一成本模型逐笔计算 |
| `costs` | 历史印花税、过户费、红利税费率表，佣金/滑点计费与成本分项 | 分配和账本必须共用 `CostSpec.charge/charge_arrays`，不要在其它模块另写费率 |
| `allocation` | 执行预算重建、按板块生成目标股数、现金/成交额限制与补回目标 | 板块规则统一走 `trading_rules`；容量限制作用于持仓变化；所有由现金或成交额缩放产生实际缺口的格子进补回 |
| `engine` | 三遍执行 + 目标股数与补回目标一起迭代、标准化日结果、持仓与绩效 | 目标股数与实际状态必须自洽，改分配逻辑要同步看 `allocation_converged` / `carry_converged` |
| `ledger` | 原始价成交、板块订单校验、公司行动、分红应收/到账、配股认购、历史税费、FIFO 红利税 | 除权日先调整持股和配股，再按板块规则执行订单；零头折现、税批次和成本分项不能丢 |
| `chunked` | 资源分块、调仓段因果求解、状态交接与结果拼接 | 资源块只控制内存；真实调仓执行日才是求解边界 |
| `metrics`/`attribution` | 绩效指标、成本与换手归因、行业暴露 | 只从日结果、成交和持仓推导，前端不重算；不假设目标权重合计为 1 |
| `store` | 策略版本与回测结果落库 | 策略版本只增不改；运行状态迁移用进程间锁串行化，`finish_run` 的全部结果表与成功状态必须同事务提交 |
| `pipeline` | 取数 → 执行 → 落库的编排与阶段事件 | 生成器只产出事件，异常一律落到运行状态 |
| `builtin` | 内置策略定义 | 定义变化会自动追加策略版本 |

## 一次回测的执行过程

1. 取数：按股票池取行情、因子与基准，指数池只取成分并集；
2. 信号：因子策略做截面标准化后线性组合、取 Top-N、等权或市值权重；提供者策略调用
   `trading/backtest/strategies/` 中注册的 `build(data, eligible, params)`，返回自定义目标权重；
   两者都在信号日收盘生成目标，下一交易日开盘执行；
3. 风险约束：单股目标权重先封顶，截下权重在同一入选池内再分配；每轮分配前按真实持仓、现金和执行价对超限目标整体缩放；
4. 规则：用持仓状态机判断每格该买还是该卖，停牌/缺执行价/涨停买入/跌停卖出拦下并记录原因，
   被拦下的格子之后每个交易日重试一次，直到成交或被下一次调仓目标覆盖；
   `reject_suspended=False` 只关闭停牌拒单记录，订单仍静默顺延到复牌，状态机不得提前记为成交；
   退市整理期股票不进入股票池、不允许买入；已持仓股票从首个可卖日开始每日按规则退出，
   停牌和跌停都不绕过，退市日仍未卖出的残仓按零价值核销并记入 `bt.liquidation`；
5. 探针：零费用跑一遍账本，拿到成交估计；
6. 基准：按 `filtered × (1 - cash_buffer)` 跑一遍账本，拿到逐日真实现金与持股数；
7. 分配：按执行日的真实现金与持股算出符合板块申报单位的目标股数；默认按
   `amount_cny × 10%` 先限制单票持仓变化，再用容量封顶、扣除 FIFO 红利税后的卖出净所得约束同日买单；
   现金或成交额约束产生实际股数缺口时创建下一交易日的补回事件；
   已有补回再次受限时延续原事件，不重复创建；换状态重算直到补回事件集合和原始调仓目标股数稳定、
   最终运行没有现金裁剪。区间末无法补足的现金缺口属于业务结果，由 `cash_pending_at_end_cells`
   单独披露，不阻断固定点收敛；
8. 最终：按目标股数跑一遍账本，得到权威的成交、持仓、费用、净值与公司行动明细；
9. 归因：从最终成交、逐日持仓和日结果计算成本分项、单/双边换手和申万一级行业暴露；
   新建策略默认按平方根模型计入冲击成本，冲击直接进入成交价；
10. 落库：日结果、持仓、成交、拒单、目标权重、分配明细、公司行动、行业暴露与绩效指标在
    同一事务写入 `data/databases/backtest.duckdb`；任一步失败都回滚本次 run 的全部结果。

## 运行示例

```python
from backtest import BacktestParams, StrategySpec, load_market_data, run_backtest

data = load_market_data("2024-01-01", "2026-10-14", ["MOM_20"],
                        universe="index:000300.SH", benchmark_code="H00300.CSI")
result = run_backtest(data, StrategySpec(), BacktestParams("2024-01-01", "2026-10-14"))
print(result.metrics["annual_return"], result.metadata["calibration"])
```

命令行（策略版本与结果自动落库）：

```bash
.venv/bin/python -m backtest --strategy mom20 --start 2024-01-01 --end 2026-09-28
.venv/bin/python -m backtest --strategy multifactor --start 2016-01-01 --end 2026-09-28 \
    --universe index:000905.SH --benchmark H00905.CSI
```

### V123 P3-01：分段报告去重

因果分段回测原先在每个调仓段都生成一次绩效指标、成本归因和完整输入快照，`_stitch()`
拼接完整区间后又整体生成一次。现在段执行只产出拼接需要的日结果、持仓、订单、分配和
公司行动明细，最终指标、归因和输入快照只在整段拼接后生成一次。段级风险约束、交易规则、
现金与持仓状态交接没有改变。

| 真实场景 | 改造前中位 | 改造后中位 | 改善 | 峰值 RSS 变化 |
|---|---:|---:|---:|---:|
| 全 A 三年、MOM_20 | 209.617s | 52.638s | 74.89% | 1628.4MB → 1602.7MB |
| 中证500 十年、多因子 | 230.632s | 97.632s | 57.67% | 1460.5MB → 1216.4MB |
| 两场景双 worker | 476.094s | 157.043s | 67.01% | 2102.3MB → 1727.5MB |

两个单任务各运行 3 次取中位数，双任务各运行 1 次；十张标准结果表的改造前后内容哈希
逐表一致。证据位于 `AiRecord/benchmarks/V123/p3-01-20261028/`。本轮为 Python 明细
生命周期和重复计算优化，没有接入 C++，C++ 替换模块数保持 14。

- 上限：单块区间 ≤ 2700 个交易日、交易日 × 股票数 ≤ 800 万格；
  **预估面板超过 800 万格时自动按时间分块**（每块约 150 万格、最多 16 块），不再直接报 `BT-401`；
- V57 在 15GiB 机器上以生产调度器实测，单任务峰值 1.57GB、双任务合计 2.06GB，
  均低于 10GB/11GB 验收线，因此本版不下调资源上限。剖析命令：
  `.venv/bin/python -m tools.monitor.backtest_profile --case all_a_3y|index_10y|dual`；
- 回测与因子评估共用一把原生计算锁：大区间回测建议单独跑。
- 每个调仓执行段独立迭代到自洽；全部段固定点稳定且无现金裁剪后标记
  `allocation_converged=true`。区间末仍有现金缺口时继续看 `cash_pending_at_end_cells`。
  若达到上限或检测到重复状态仍未稳定，仍以最后一次结果为准并保留 `false`，不伪造收敛。

## 边界

提供者接口覆盖“行情/因子 → 目标权重”的日频研究策略，支持择时、配对和动态目标权重。
研究基线另有一个不从常规发现列表暴露的 `factor_rank` 提供者，位于
`trading/backtest/strategies/_factor_rank.py`，用于 P0 的全因子截面分位等权基线。
需要真实持仓的提供者声明 `uses_position_state=True`，`build` 接收账本生成的逐日
`ProviderState`：现金、组合价值、持仓股数、平均成本、浮动收益、建仓以来最高收盘价和
最近清仓。提供者只读取状态，不模拟成交。止损、移动止损和按持仓动态加减仓走执行层
状态钩子，状态反馈按整段回测重复到目标权重稳定，最多 20 遍；未收敛直接失败。
提供者仍不能访问未来数据，也不能依赖块外未落盘的历史行情。前端新建策略页支持
因子 Top-N 和结构化提供者参数两种模式，二者与 HTTP API、Python 共用同一条策略版本路径。

- 提供者名称、版本、参数和必需因子在创建/运行前校验；代码改动必须提升版本。创建策略时
  策略版本与提供者源码修订同事务提交，完整源码、源码哈希和数据分项摘要仍进入
  `metadata.snapshot`；同版本换源码会被 `BT-701` 拒绝。
- 提供者返回的权重先经过 eligible 和权重合法性校验，再由执行层统一施加风险上限；分块准备
  阶段不会提前按风险上限改写目标，避免风险统计被清零。

## 分块回测

面板超过 800 万格（约等于全 A 五年）时，`pipeline.iter_run` 会按时间自动切块准备信号，
命令与接口不变。每块面板控制在约 150 万格以内；之后从整段目标中按真实调仓执行日划分
逻辑段，逐段交接权威现金、持仓、估值价和规则状态。

块边界口径：

- 第 k>1 块的窗口 = 上一块最后一个交易日（**预热行**）+ 本块交易日；预热行只把交易标记
  与信号平移到本块首日，不下单、不改状态机、不进结果；
- **状态交接**：预热行只提供价格口径，账本直接从上一块收盘现金、持股、税批次和应收分红起步；
- 调仓日掩码、退市核销候选、指数成分口径都按**整段区间**算好再交给各块，
  避免块尾落在周中或块边界正好是退市日时口径错位；
- 资源块只决定信号准备和数据读取的内存规模；单块与分块从同一份整段目标生成相同调仓段；
- 每个调仓段使用上一段最终真实状态求解，现金补回在下一次真实调仓前逐日推进；
- `metadata.execution.mode = causal_segmented`，`chunk_count` 是资源块数，`segment_count` 是调仓段数。

## 输入快照

每次运行会在读取面板前生成一次范围级内容摘要，单块与分块共用同一份 `snapshot_id`。
行情、交易日历、股票池、因子、公司行动、行业、基准和规则分别记录摘要；区间外数据刷新
不改变快照，区间内实际输入变化会改变对应分项。快照落在 `bt.input_snapshot`，运行表与
API 详情同时返回 `snapshot_id`。旧运行没有快照时保持为空，不回填。

规则分项中的 `execution_model` 记录执行模型版本，以及引擎、账本、分配、风控、成本和信号等
核心模块的逐文件 SHA-256。公司行动模型和 `rights_issue_policy=cash_limited` 也进入快照。
执行代码变化会自动改变 `snapshot_id`；快照 schema 升级到 v4 后，旧 v1/v2/v3 快照仍按原 JSON 读取。

验证状态：合成面板的多组切点、跨块退市 + 涨停 + 停牌，以及沪深300 池
`2025-01-01 ~ 2026-10-14` 强制切 3 块，日结果、订单、持仓、目标权重、拒单、清算、
分配明细、持仓记录、指标和校准字段都与单块运行**逐位一致**。真实对照均为 2001 笔订单、
V36 全 A `2016-01-01 ~ 2026-10-14` 实测为 8 个资源块、129 个调仓段，全部收敛，
单段最大 23 轮；`cash_clipped_cells=0`、目标股数差额 0、区间末现金缺口 0。
运行耗时 29 分 36 秒，峰值 RSS 约 6.02GB。对应 run_id 为
`e832b0cb9200485faae95dd9b10b7521`，审计退出码 0。

退市处置另有独立手工账本黄金用例：整理期首个可卖日正常退出、退市日停牌无法卖出时的
零价值核销、区间末退市、连续跌停和成交额容量不足后的残仓核销都能逐项对上；
显式移除核销候选时，区间末残留退市持仓会直接报错，确保用例能区分核销机制是否生效。

风险约束支持单股上限、时点申万一级行业上限与单边换手上限。行业分类在 `2021-12-13` 前使用
SW2014，之后使用 SW2021；SW2021 缺失时沿用最近已知行业并标记，最早记录晚于上市日时向前补到
上市日。行业缺失或冲突会终止运行；换手限制导致的历史持仓暂时超限单独披露。仍不做做空、
融资融券、分钟级撮合与 ML。
前端支持完整参数的新建策略、运行删除、2～4 次运行共同区间对比，以及单运行日超额收益图；
新建策略与内置策略走同一条版本存储和执行路径。

接口与流事件见 `docs/trading/backtest/api.md`。

日志按模块写到 `logs/trading/backtest/<模块>/<起始时间>-<结束时间>.log`，结束时间随最后一条记录推进，
128MB 前轮转；依赖安装与校验见 `docs/core/ops/dependencies.md`。
