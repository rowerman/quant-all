# 执行账本与 VectorBT 适配边界

P0-1 起正式执行路径改用 `trading/backtest/ledger.py` 的原始价账本。账本负责真实成交股数、
现金分红、送转、配股、零头折现和 FIFO 红利税；VectorBT 仍作为历史口径对照和依赖版本记录，
不再负责正式运行的现金与持股记账。外层信号、规则过滤、资金分配、风险约束和固定点
迭代没有改变。

## 为什么最终一遍按目标股数下单

VectorBT 的 `size_type="targetpercent"` 让下单量随真实组合价值浮动，适配层不用维护账本；
但它有两个绕不开的问题：

1. 目标金额不足**最小申报量**时整只股票买不进（全 A 三年实测 32/889 个目标格完全没建仓）；
2. 目标权重合计 1.0 时，费用、滑点与申报单位取整会让现金不够，VectorBT 按确定性顺序
   处理订单，排在后面的格子被整笔裁掉（A3），偏差最大等于一整个仓位。

因此最终一遍改成 `size_type="targetamount"`：目标股数由 `trading/backtest/allocation.py` 算出，
下单量天然符合所属板块的申报单位，也不会再把队尾格子整笔裁掉。

## 三遍执行

| 遍 | 目标与费用 | 作用 |
|---|---|---|
| 探针 | 未过滤目标权重、零费用 | 提供成交方向兜底 |
| 基准 | 规则过滤后的目标权重 × `1 - cash_buffer`，带完整费用 | 提供逐日真实现金与持股数，作为第一次分配的预算来源 |
| 最终 | 分配出的**目标股数** + 统一成本模型 | 权威的现金、持仓、费用与净值 |

## 资金分配

分配只做一件事：把「执行日开盘时刻的组合价值」按现金缓冲折成可用预算，再换成符合板块规则的目标股数。

新策略默认启用 10% 成交额参与率；目标股数转换后按执行日未复权成交额限制每只股票的持仓变化：
`max_trade_value = amount_cny × max_participation_rate`。容量造成的股数缺口会沿现有补回状态机每日重试；
缺失或为零的成交额不使用静态兜底。

1. **预算**：`cash(base, t-1) + Σ 持股(base, t-1) × 执行价(t)`，执行价取开盘价、停牌用前收盘；
2. **目标市值**：`预算 × (1 - cash_buffer) × 目标权重`。目标权重是「占整个组合的比例」，
   即使当天只有少数格子下单（重试日）也按整个组合价值算，不能拿这些格子自己的市值当基准；
3. **目标股数**：空仓格向下取整到最小申报量；已有持仓按「差够合法申报单位才动」调整；
4. **容量与现金约束**：先按成交额参与率限制每只股票的持仓变化，再按容量封顶后的
   卖出净所得计算本行可用现金。被容量限制的卖单不能为同日买单提供未成交资金。
   买单的成交额、滑点和最低佣金不能超过「开盘现金 + 实际卖出净所得」；
   卖出净所得已经扣除滑点、佣金、印花税，并预留上一遍账本结算的 FIFO 红利税。
   超限时先等比缩小，再按交易单位回退到可成交股数
   （卖不掉的持仓拿不到现金，只能少买，而不是买空）；
   被缩小的行记 `cash_shrunk_cells`；原始买单确实因现金比例缩放产生实际股数缺口时，
   记 `cash_limited` 并创建现金补回事件。已有补回再次被现金缩小时只记录缩水股数并
   延续原事件，不重复创建补回事件。普通申报单位取整造成的股数差不进入补回；
5. **余量补最小申报量**：先用取整余量把「最小订单都装不下」的目标格补到最小申报量，
   余量不超过「开盘现金 + 本行持仓市值」；余量不够就保持 0 股，记 `unaffordable`，不剔除也不超配。

分配按**调仓执行段**因果推进：第一段从回测起点到下一次调仓前一日，之后每个真实调仓执行日
开启新段。后一段只使用前一段已经确定的真实现金、持仓、估值价和规则状态；段内再迭代现金补回，
直到目标股数与补回事件稳定、最终运行没有现金裁剪。段末无法补足的现金缺口单独计入
`cash_pending_at_end_cells`，不再阻止固定点收敛。这样十年区间不会再靠整段迭代逐月传播状态。
单段用尽上限或检测到重复状态时仍标 `allocation_converged=false`，不伪造收敛。

资源分块只负责限制取数和信号准备的内存，不是求解边界。单资源块和多资源块都会从整段目标中
得到相同的调仓执行段，因此切点不会改变订单和结果。运行元数据使用
`execution.mode = causal_segmented`，并记录资源块数、调仓段数、迭代合计和未收敛段数。

### 现金补回

因卖不掉而少买的格子不能就这么算了：被现金缩小的目标格记下来，**下一个交易日继续按同一个目标权重补**，
直到补齐或者下一次调仓把它覆盖（`bt.allocation.cash_limited` 标出补回格，`cash_shrunk_shares` 记缩水股数）。
补回目标用「占整个组合的目标权重」表达，重试日按当天的预算与现金重新换算股数，
钱没到账就还是补不上、继续留在待重试状态；被停牌或涨停拦下时走规则层那一套重试。

补回目标来自分配结果、分配结果又依赖补回目标，因此和分配一起迭代：
第一轮以及后续每轮都把未完成事件铺到下一次真实调仓之前，再按本轮分配结果裁掉已经补齐的部分。
`carry_iterations` 是补回目标变过几次，`carry_converged` 表示「本轮用的补回目标 = 由分配结果派生出的」。
现金补回按所有原始现金缩放造成的实际缺口处理；重试日的缩水不重复建事件。真实验收需要同时关注现金缩水行数、进入补回事件数、
补回尝试次数和区间末未补回格数。区间末缺口是允许保留的业务状态，不等于分配未收敛。
全 A 三年没有触发过现金缩小时，补回逻辑不改变原有结果。

## 费用校准

正式执行路径已经改用 `trading/backtest/ledger.py` 的原始价账本，账本在成交时直接知道
股票代码、板块、成交方向、股数、原始开盘价和成交日，因此不再需要「日期 × 股票」
费率矩阵，也不需要靠成交估计反推买卖方向。

所有成交统一调用 `CostSpec.charge`：佣金按笔最低 5 元，印花税按历史生效日期，
过户费按沪深北市场和日期，红利税按卖出日政策和 FIFO 批次；佣金、印花税、过户费
逐笔按分四舍五入。资金分配用同一个 `charge_arrays` 估算现金约束，账本再用标量
`charge` 精确记账，两者不会出现口径漂移。

`fee_matrix_max_diff` 保留为审计字段，含义改为「实际 `Fees` 与成本模型逐笔重算值的
最大偏差」；新实现应为 0。

## 规则层

停牌、涨停买入、跌停卖出属于项目规则，由 `trading/backtest/orders.py` 的持仓状态机拦截：

- 状态只在**实际下单成功**时更新；被拦下的格子进入待重试状态，
  之后**每个交易日**都尝试一次，直到成交或者下一个调仓执行日的目标把它覆盖；
- 被拦的那一天写回 `NaN`（不下单、保持原仓位），原因写入 `bt.rejection`；
  同一事件的后续重试不再重复写拒单，只累加 `retry_attempts`；
- 区间结束时仍未解决的普通格子保留仓位并记 `pending_at_end_cells`；
- 退市整理期股票不买入；已持仓股票从首个可卖日开始按停牌/跌停规则退出，
  退市日仍未卖出的残仓按零价值核销，明细落 `bt.liquidation`；
- 被现金缩小的补回目标也走同一套重试口径（`cash_retry_attempts` / `cash_retry_filled_cells`）；
  补回只缺「买回来」这一侧，因此按买入意图处理：涨停买不到明天再补，卖不卖得掉不影响它。

重试不引入新配置项：调仓执行日的目标矩阵整行有值，天然覆盖上一期没卖掉／没买进的状态；
非调仓日的重试格是「记忆下来的原目标权重」，在重试日按当天的组合价值重新解释。

## 结果与自检

运行元数据的 `calibration` 是每次回测的自检口径：

| 字段 | 含义 |
|---|---|
| `cash_buffer` | 执行层预留的现金比例 |
| `max_participation_rate` | 单票单日未复权成交额参与率；默认 10%，`None` 表示关闭 |
| `allocation_iterations` / `allocation_converged` | 单段最大迭代次数与所有调仓段固定点是否稳定；期末现金缺口看下一项 |
| `allocation_segments` / `allocation_iterations_total` | 调仓段数与各段迭代次数合计 |
| `allocation_iterations_max` / `nonconverged_segments` | 单段最大迭代次数与未收敛段数 |
| `probe_orders` / `final_orders` | 探针与最终一遍的成交笔数 |
| `planned_orders` / `rebalance_orders` | 计划下单格数 / 其中方向未知的再平衡格数 |
| `rejected_orders` | 规则拒单笔数，与 `bt.rejection` 逐条一致 |
| `forced_liquidations` | 退市零价值核销笔数，与 `bt.liquidation` 逐条一致 |
| `forced_exit_orders` | 整理期/退市日强制退出成交笔数，与 `bt.order.forced_exit` 一致 |
| `delisting_residual_shares_at_end` | 区间末已知退市残留股数，必须为 0 |
| `retry_attempts` | 被拦交易在非首日重试的尝试次数（含失败） |
| `retried_filled_cells` | 靠每日重试在非调仓日成交的格子数 |
| `pending_at_end_cells` | 区间结束时仍未解决的待重试格子数（仓位保留） |
| `t_plus_1_blocked_cells` / `t_plus_1_blocked_shares` / `t_plus_1_blocked_value` | 严格 T+1 拦截的卖出格数、股数与金额；当前日频策略应为 0 |
| `cash_shrunk_cells` | 被现金约束缩小买单的格数（含最小申报单位内的残差） |
| `cash_limited_cells` / `cash_limited_value` | 进入补回的现金缩水格数与缩水金额 |
| `cash_retry_attempts` / `cash_retry_filled_cells` | 现金补回的尝试格次与真正补齐的格数 |
| `cash_pending_at_end_cells` | 区间结束时仍被现金限制、来不及补的格数，不影响固定点收敛标记 |
| `carry_iterations` / `carry_converged` | 补回目标变过几次、是否与本轮分配结果自洽 |
| `allocated_cells` | 分配出目标股数（>0）的格数 |
| `bumped_min_order_cells` | 用取整余量补到最小申报量的格数 |
| `unaffordable_min_order_cells` | 最小申报量金额超出可用预算、保持 0 股的格数 |
| `below_min_order_cells` | 已有持仓因差额不足最小申报量而未成交的格数 |
| `no_price_cells` | 缺执行价、未下单的格数 |
| `fallback_fee_orders` | 没有成交估计、按意图方向计费笔数 |
| `fee_matrix_max_diff` | 逐笔费用核对的最大偏差（元），应为 0 |
| `cash_clipped_cells` / `allocation_gap_max_shares` | 实际持股与目标股数不一致的格数与最大差额，应接近 0 |
| `target_cells`、`weight_deviation_*` | 下单格数与实际权重偏差的中位数 / 95 分位 / 最大值 / 超 1% 格数 |

`weight_deviation_*` 仍按**信号日目标权重**比较，因此包含执行层 2% 现金缓冲的系统性预留
（每格约 `0.02 / 持仓只数`）与最小手数带来的取整偏差；每日重试的格子也计入目标格，
所以口径比 V23 略严（一个格子还在等补单时，它的偏差会被照实统计）。

## 已知边界

- 单股上限在信号目标层完成封顶；换手上限在每轮分配前按上一遍真实组合状态重算。
  两者都不直接截断最终订单，以免破坏规则拒单、现金补回和目标股数固定点。
- 换手口径为含现金的单边换手：`0.5 × (股票权重绝对变化之和 + 现金权重绝对变化)`。
  现有超配持仓在换手上限下可分多次回落。

- 目标仓位小于最小申报量的高价股，只有在取整余量够时才补得进；组合缩水后最小订单占组合比例变大，
  这类格子的实际权重会明显高于目标（全 A 三年最大偏差 7.1%），这是最小手数的真实约束；
- 被规则拦下的持仓当天卖不掉，之后每个交易日重试；等待期间组合偏重这些名字，其余格子的
  目标按可换手部分等比缩小，停牌到区间结束的仓位只能保留（记 `pending_at_end_cells`）；
- 被现金缩小且产生实际股数缺口的买单都按日补回；普通申报单位取整残差不进入待重试。
- 补回的是「该格的目标权重」而不是缺的那几股：金额按补回当天的预算与现金重算，
  所以补齐时可能与当天的目标差一个申报单位以内（十年中证500 的 10 格补齐后都在目标的 0.9 倍以上）；
- 分配不收敛时（`allocation_converged=false`）以最后一次迭代为准，指标照常给出；
  `allocation_converged=true` 但 `cash_pending_at_end_cells>0` 表示固定点稳定、只是区间末缺现金。

## 什么时候升级

如果以后需要逐单动态逻辑（部分成交、资金重排、盘中撮合），再评估 `from_order_func`：
它的回调能拿到真实持仓和现金，并且在 `order_nb` 里逐单设置费用、方向与取整。
当前用「三遍执行 + 迭代分配」已经能拿到真实状态并给出目标股数，不必上 numba 回调。
