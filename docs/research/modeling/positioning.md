# ML 模型在量化研究链路中的定位

日期：2026-10-19

本文回答两个容易混淆的问题：

1. ML 产出的分数，是不是用于策略构建、决定因子如何加权组合？
2. 模型训练出来以后，是不是就一直保持不变？

先给结论：

- 是，但更准确地说，ML 输出的是“预测分数或截面排序”，策略层再把分数变成目标权重。ML 不直接决定买卖，也不绕过组合约束和交易规则。
- 不是。单次回测里，模型版本必须冻结以保证可复现；研究和生产中，模型要按版本迭代、滚动重训、监控和淘汰。

## 1. 一句话定位

ML 是“因子值 → 预测分数”的估计器，不是策略本身。

它回答的问题是：

> 给定一只股票在 t 日收盘时可见的因子和上下文，它在未来 h 个交易日的收益，或者它在全市场中的相对排名，大概会是什么样？

它不回答的问题包括：

- 今天应该买多少？
- 单票最多放多少权重？
- 行业暴露要不要限制？
- 涨停买不进怎么办？
- 印花税、佣金、冲击成本是多少？

这些问题仍然由组合构建、风险约束和回测执行层回答。

## 2. 当前链路与 ML 的位置

当前项目的主链路可以概括为：

```text
行情与辅助数据
    ↓
清洗、复权、停牌、涨跌停、生命周期
    ↓
因子值（core/factors/ + data/factors/）
    ↓
因子质量评估（research/evaluation/calculate/）
    ↓
alpha 模型（ML）              ← 新增层
    ↓
预测分数 / 截面排序
    ↓
组合构建（Top-N、权重、行业/规模、换手）
    ↓
回测执行（T+1、涨跌停、停牌、成本、账本）
    ↓
归因、监控、重训、版本迭代
```

对应到代码，ML 最适合替换的是 `trading/backtest/signals.py` 里 `build_scores` 的“线性加权”这一步：

```text
现在：score = w1 * MOM_20 + w2 * EP_TTM + w3 * VOL_20 + ...
以后：score = model(MOM_20, EP_TTM, VOL_20, ..., 上下文)
```

后面的 `build_target_weights`、股票池过滤、订单分配、T+1、涨跌停、成本计算都不需要因为引入 ML 而重写。

各层的职责可以这样看：

| 环节 | 回答的问题 | 输入 | 输出 | 是否由 ML 负责 |
|---|---|---|---|---|
| 数据与标签 | t 日能看到什么，未来收益是多少 | 行情、财务、辅助表 | 因子值、`md.fwd_return` | 否 |
| 因子评估 | 单个因子有没有信息、稳不稳定 | 因子值、标签、股票池 | IC、ICIR、分箱、换手、暴露 | 否 |
| alpha 模型 | 多个因子合在一起，未来收益/排名怎么预测 | 因子矩阵、标签、样本权重 | 预测分数或排序 | 是 |
| 组合构建 | 分数怎么变成持仓 | 分数、股票池、风险约束 | 目标权重 | 否 |
| 回测执行 | 目标能不能成交、成本多少 | 目标权重、行情、规则 | 订单、成交、净值 | 否 |
| 监控与重训 | 模型有没有衰减，要不要换版本 | 样本外表现、特征分布 | 新模型版本或停用 | 是，属于模型生命周期 |

### 2.1 组合构建和策略层是什么关系

组合构建和策略层不是一回事。组合构建是策略的一个核心子模块，但不是策略的全部。

可以把策略理解成一整套决策规则：

```text
策略
├── 股票池：能买什么
├── 信号：谁更好
├── 组合构建：每只买多少
│   ├── 选股方式（Top-N、分位数、优化器）
│   ├── 权重方式（等权、市值权重、风险权重）
│   └── 约束（单票上限、行业上限、换手上限）
├── 调仓：什么时候换
├── 执行：怎么成交（T+1、涨跌停、停牌、申报单位）
├── 成本：佣金、印花税、滑点、冲击
└── 基准：和谁比较
```

组合构建只负责“分数怎么变成仓位”这一段。它回答的是：

- 模型说 A 比 B 好，A 买 3% 还是 5%？
- 只买前 30 只还是前 100 只？
- 行业超配要不要限制？
- 换手太高要不要压？

策略还要回答更多问题：股票池是什么、信号怎么来、多久调一次、涨停买不进怎么办、成本扣多少、和什么基准比。

在本项目里，策略的边界写在 `StrategySpec` 中：

| 策略组成 | 本项目字段 | 回答的问题 |
|---|---|---|
| 股票池 | `universe` | 能买什么 |
| 信号 | `signal.factors` / `signal.provider` | 谁更好 |
| 组合构建 | `portfolio` | 买哪些、买多少 |
| 风险约束 | `risk` | 单票、行业、换手如何限制 |
| 调仓 | `rebalance` | 什么时候换 |
| 执行 | `execution` | T+1、涨跌停、停牌、申报单位 |
| 成本 | `costs` | 佣金、印花税、滑点、冲击 |
| 基准 | `benchmark` | 和谁比较 |

所以在这个项目里，策略不是“一套组合构建逻辑”，而是上述整套配置。任何一个字段发生实质变化，都会形成一个新的策略版本。

举两个例子：

- 同一个 ML 分数，用 Top-30 等权、月度调仓，和用 Top-100 风险权重、周度调仓、行业上限 20%，是两个不同的策略。
- 同样的 Top-30 等权月度调仓，一个用动量信号，一个用 ML 信号，也是两个不同的策略。

组合构建之所以重要，是因为它经常决定“同样的 alpha 能不能变成更好的组合”。信号负责找方向，组合构建负责控制暴露、分散风险、压低换手、适配容量。但它不能替代信号，也不能替代执行和成本。

对研究来说，最好把两层分开做实验：

- 比较 ML 和线性模型时，固定股票池、组合构建、调仓、执行和成本，只换信号；
- 研究组合构建时，固定信号，只改选股、权重和约束。

否则同时改信号和组合构建，最后很难判断收益到底来自哪里。

一句话总结：策略是整套决策规则，组合构建只是其中“如何把分数变成仓位”的一段。构建策略不等于只构建组合构建逻辑，但组合构建往往是 alpha 之外最影响策略结果的环节。

## 3. ML 到底在学什么

### 3.1 学的是一个条件预测函数

从数学上看，ML 学的是一个映射：

```text
f(因子值, 股票特征, 市场状态) → 未来收益的条件期望，或未来收益的截面排名
```

例如：

```text
E[r(t+1, t+5) | MOM_20, VOL_20, EP_TTM, ROE, log_mv, ...]
```

在实际使用中，不一定要预测精确收益。对 Top-N 选股来说，预测“相对排名”通常比预测“精确收益”更有用，也更稳健。

### 3.2 “决定因子权重”是一个简化说法

线性组合里，权重是显式的：

```text
score = 0.6 * MOM_20 - 0.4 * VOL_20 + 0.3 * EP_TTM
```

这里的 0.6、-0.4、0.3 就是固定的因子权重，含义很清楚。

ML 模型不一定会给出这样一组固定权重：

- 线性模型（Ridge、ElasticNet）仍然是一组系数，可以理解为权重；
- 树模型（LightGBM）是把特征空间切成很多区域，每个区域给一个预测值。某个因子在不同区域的重要性不同，不存在一组全局固定的“因子权重”；
- 神经网络更复杂，因子的作用分布在大量参数和交互项里。

所以更准确的说法是：

> ML 学习的是“因子在不同股票特征、不同市场状态下应该如何组合”，而不是简单地给每个因子分配一个永久不变的权重。

特征重要性（gain、SHAP 等）可以帮助理解模型，但它不是组合权重，也不是因果结论。一个因子 importance 高，不代表应该给它更高的仓位权重。

### 3.3 线性组合和 ML 的区别

| 维度 | 线性组合 | ML 模型 |
|---|---|---|
| 形式 | `score = Σ w_i * f_i` | `score = f(f_1, ..., f_k, context)` |
| 因子权重 | 固定、显式 | 隐式、随特征区域或市场状态变化 |
| 非线性 | 需要手工做变换 | 可以从数据中学习 |
| 因子交互 | 默认没有 | 可以学习，例如“低波动时动量更有效” |
| 缺失值 | 需要显式填充 | 树模型可以直接处理 |
| 可解释性 | 强 | 中等或较弱 |
| 过拟合风险 | 较低 | 较高，尤其是特征多、样本少时 |
| 适用场景 | 因子少、关系稳定、需要强解释 | 因子多、关系复杂、样本足够、接受模型风险 |

线性模型本身也是 ML。真正的问题不是“要不要用 ML”，而是：

> 在简单的线性组合之外，数据里是否真的存在稳定的非线性或交互结构，足以抵消模型估计误差和过拟合风险？

如果答案是否定的，最诚实的结论就是继续用线性模型。

### 3.4 一个具体例子

假设只有三个因子：

- `MOM_20`：过去 20 日动量；
- `VOL_20`：过去 20 日波动率；
- `EP_TTM`：盈利收益率。

线性模型可能给出：

```text
score = 0.5 * MOM_20 - 0.3 * VOL_20 + 0.2 * EP_TTM
```

这组权重对所有股票、所有市场状态都一样。

ML 可能学到的是：

- 当波动率较低、流动性较好时，动量的正向作用更强；
- 当波动率很高或刚刚经历极端上涨时，动量可能转为反转；
- 当盈利收益率高、同时 ROE 也高时，价值因子的作用更可靠；
- 当市场整体波动升高时，模型会降低动量因子的有效权重。

这些关系不是一句“动量因子权重 0.5”能表达的。ML 的意义在于：它可以从数据中估计这些条件关系，而不是要求研究员事先把所有交互项手工写出来。

当然，这也带来风险：如果这些关系只是历史样本里的巧合，模型就会学到假规律。所以 ML 的价值必须由严格的样本外结果来证明。

### 3.5 模型输出的是什么

模型可以输出几种不同的东西：

- 未来收益的预测值；
- 未来收益的截面排名或百分位；
- 进入未来收益前 20% 的概率；
- 相对基准的超额收益预测。

对当前项目的 Top-N 策略，最实用的是“截面排名分数”：

```text
每个交易日，对全市场股票打分，然后取分数最高的 N 只。
```

分数本身不需要有绝对的经济含义。0.8 不一定代表 80% 的上涨概率，除非模型专门做了概率校准。对排序选股来说，只要同一天内不同股票的相对顺序稳定、有效，就足够了。

分数也不等于目标权重。分数只回答“谁更好”，组合构建才回答“每只买多少”。

### 3.6 模型分数和因子到底是什么关系

可以用一句话概括：

> 因子是模型的输入，模型分数是因子经过学习后得到的“组合信号”。它本身也可以看成一个新的衍生因子。

这里有三个不同层次的对象，不要混在一起：

| 对象 | 例子 | 角色 |
|---|---|---|
| 原始因子 | `MOM_20`、`EP_TTM`、`VOL_20` | 模型输入，可观测的股票特征 |
| 模型分数 | 0.83、0.41、-0.12 | 模型输出，用于截面排序的信号 |
| 组合权重 | 3%、2%、0% | 策略层输出，真正要买的仓位 |

模型分数不是原始因子，但它是因子的函数：

```text
score = model(MOM_20, EP_TTM, VOL_20, ROE, log_mv, ...)
```

所以模型和因子的关系是明确的：因子提供信息，模型决定这些信息怎么组合。只是这个“怎么组合”不一定是固定的线性权重。

线性模型里，关系最清楚：

```text
score = 0.5 * MOM_20 - 0.3 * VOL_20 + 0.2 * EP_TTM
```

这里每个因子的系数就是它的权重，可以直接解释。

树模型里，关系是条件化的。模型可能学到：

- 当 `VOL_20` 较低时，`MOM_20` 的正向作用更强；
- 当 `VOL_20` 很高时，`MOM_20` 的作用减弱甚至反转；
- 当 `ROE` 较高时，`EP_TTM` 的作用更可靠。

这时不存在一组全局固定的“因子权重”。模型分数仍然是因子的函数，只是这个函数在不同特征区域里不一样。

如果想观察模型分数和因子的关系，可以用下面几种方法：

1. **分数与单因子的截面相关性**：每个交易日算一次 `corr(score, factor_j)`，看模型分数主要跟哪些因子同向或反向。
2. **分数对因子的截面回归**：每个交易日用 `score` 对全部因子做回归，得到当天的有效暴露；再把每天的系数连成时间序列，看暴露是否稳定。
3. **SHAP 或 partial dependence**：看某个因子在模型预测中的边际作用，尤其适合树模型。
4. **消融实验**：去掉一个因子或一组因子，重新训练，比较样本外 IC、Top-N 净收益和换手。这个最能说明“这个因子对模型有没有增量”。
5. **组合暴露分析**：看模型选出来的股票在行业、市值、波动、流动性上的暴露，判断它是不是变成了某种风格 bet。

要注意：这些方法描述的是“模型在使用什么信息”，不是因果结论。相关性高、SHAP 大，都不等于这个因子一定能赚钱；相关因子之间还会分摊重要性。

模型分数和单因子相关性不高，也不代表模型没有用。举个简单的例子：

- 动量因子单独看很弱；
- 波动因子单独看也很弱；
- 但“低波动 + 高动量”的组合可能很强。

这时模型分数与两个单因子的线性相关性都不高，却仍然能预测未来收益。这正是模型层 IC 和单因子 IC 的区别：单因子 IC 看的是边际信息，模型 IC 看的是组合后的信息。

### 3.7 模型分数为什么也能计算 IC

IC 的定义不依赖这个变量叫不叫“因子”。IC 本质上就是：

> 任意一个截面分数，与未来收益在截面上的秩相关。

对第 t 个交易日：

```text
IC_t = corr(rank(score_i,t), rank(ret_i,t→t+h))
```

其中 `i` 是当天股票池里的股票。把所有交易日的 `IC_t` 连起来，就得到 IC 时间序列：

```text
IC_mean = mean(IC_t)
ICIR = IC_mean / std(IC_t)
t = IC_mean / (std(IC_t) / sqrt(T))
```

所以下面这些都可以算 IC：

- 原始因子值；
- 模型预测的未来收益；
- 模型输出的排名分数；
- 模型输出的上涨概率；
- 线性组合后的综合分数。

IC 只关心“排序对不对”，不关心分数的绝对大小。把分数乘以 10、取对数、换成百分位，只要排序不变，RankIC 就不变。

一个三只股票的例子：

| 股票 | 模型分数 | 未来 5 日收益 |
|---|---:|---:|
| A | 0.9 | 3% |
| B | 0.5 | 1% |
| C | 0.1 | -2% |

分数排序是 A > B > C，收益排序也是 A > B > C，这一天的 RankIC 就是 1。

如果收益变成 B > A > C，排序不完全一致，RankIC 就会小于 1。具体数值由秩相关公式计算。

在本项目里，计算模型 IC 的流程可以直接复用现有数据：

1. 从 `data/models/models/<model_id>/predictions` 读取预测面板：

   ```text
   trade_date, stock_code, score
   ```

2. 和 `md.fwd_return` 按 `trade_date`、`stock_code` join，取与模型训练 horizon 一致的标签，例如 `fwd_ret_open_5`。
3. 和股票池标记 join，只保留 `eligible=True` 的样本。
4. 按 `trade_date` 分组，对 `score` 和标签做 Spearman 相关，得到每日 RankIC。
5. 汇总均值、标准差、ICIR、t 值、胜率，并做分年度和分市场状态的稳定性检查。

可以复用 `calculate` 里的底层函数：

- `calculate.daily.daily_ic`：计算每日 IC / RankIC；
- `calculate.binning`：做分箱和分层收益；
- `calculate.stats.series_stats`：汇总均值、ICIR、t 值等。

这些函数原本接收的是“因子列 + 标签列”的面板。模型分数只需要作为 `factor` 或 `score` 列传进去，不需要先把模型注册成原始因子。为了概念清楚，建议把模型输出放在独立的 `data/models/` 里，不要混进 `data/factors/` 的原始因子库。

模型 IC 和单因子 IC 的区别可以这样理解：

| 指标 | 回答的问题 |
|---|---|
| 单因子 IC | 这一个因子单独使用时，还有多少预测力？ |
| 模型 IC | 把多个因子组合起来后，整体信号还有多少预测力？ |
| 组合层收益 | 这个信号扣费后，能不能变成可交易的 Top-N 组合？ |

比较模型和因子时，必须保证日期、股票池、标签周期、缺失处理一致。否则 IC 的差异可能来自口径，而不是模型。

还有一点很重要：模型 IC 必须用样本外预测计算。用训练集里的预测算 IC，只能说明模型拟合得好，不能说明它有预测能力。模型训练时用的损失函数和 IC 也不是一回事：一个模型可能有较低的均方误差，但排序能力一般；也可能 IC 不错，但组合层因为换手和成本而不赚钱。所以 IC 只是中间指标，最终还要看扣费后的组合结果。

## 4. ML 的真正意义

### 4.1 处理非线性和因子交互

多因子之间经常不是简单相加的关系。例如：

- 动量在低波动环境中可能更有效；
- 价值因子需要质量因子配合，否则可能是“价值陷阱”；
- 小市值因子在流动性紧张时可能失效；
- 极端估值、极端涨跌幅附近的收益关系往往是非线性的。

线性模型要处理这些关系，需要手工构造交互项、平方项、分组项。ML 可以自动学习一部分，但前提是数据里确实有足够稳定的样本。

### 4.2 让因子权重随状态变化

市场风格会切换。同一个因子在 2015 年、2018 年、2021 年和 2024 年的有效性可能完全不同。

固定权重的线性组合，要么长期持有同一组权重，要么由研究员手动调权重。ML 可以根据市场状态、波动率、流动性、股票特征等，动态地改变因子的相对重要性。

这里的“动态”不是指模型每天变一次参数，而是指模型的预测函数本身是条件化的：同样的 `MOM_20` 值，在不同波动率、不同行业、不同市值下，可能得到不同的分数贡献。

### 4.3 把“因子组合”变成一个可验证的问题

手工设定多因子权重，很容易变成“拍脑袋”或反复试参数。ML 提供了一个更系统的框架：

1. 明确标签：预测未来 5 日还是 20 日收益；
2. 明确特征：用哪些因子、怎么处理缺失、怎么中性化；
3. 明确切分：训练、验证、测试怎么分，怎么防止泄漏；
4. 明确基线：单因子、线性组合、Ridge；
5. 明确评估：样本外 IC、分箱、Top-N 净收益、换手、回撤。

即使最后发现线性模型最好，这个研究框架本身也是有价值的，因为它让“因子怎么组合”从经验判断变成了可重复的实验。

### 4.4 评估新因子的增量价值

因子库里有很多相关性较高的因子。单看某个因子的 IC，不能判断它在多因子模型里是否还有增量。

ML 可以用“加入这个因子前后，样本外组合表现是否改善”来判断增量价值：

- 加入后 RankIC 提升，且逐年稳定；
- Top-N 净收益提升，换手没有明显恶化；
- 特征重要性稳定，不是只在一小段样本里有效；
- 与已有因子的相关性不高，提供的是新信息。

这比只看单因子 IC 更接近真实投资决策。

### 4.5 为后续的 meta-labeling、择时和风险模型打基础

第一版 ML 通常做“截面选股”。有了这套数据、标签、训练和评估管线之后，可以继续做：

- meta-labeling：先有一个基础信号，再用分类器判断“这次信号值不值得交易”，提高胜率或降低换手；
- 择时：预测市场整体收益或风险状态，决定仓位；
- 风险模型：预测波动率、相关性或尾部风险；
- 执行模型：预测短期冲击和成交质量。

这些任务的标签和评估方式不同，不应该和第一版截面选股混在一起。先把截面 alpha 模型做好，再考虑扩展。

### 4.6 ML 不会创造不存在的 alpha

这是最重要的一点。

ML 只能从已有特征中提取信息。如果因子本身没有预测力，或者数据有前视偏差、幸存者偏差、停牌/涨跌停处理错误，ML 只会把这些错误拟合得更漂亮。

ML 也不能替代：

- 经济逻辑和因子研究；
- 数据清洗和时点校验；
- 组合约束和风险管理；
- 交易成本和容量评估；
- 样本外验证和模型监控。

它的作用是把“多个因子的组合方式”变成一个可学习的函数，而不是凭空产生新的信息来源。

## 5. 模型产出后会发生什么

### 5.1 单次回测：模型版本必须冻结

在一次回测或一次实盘运行中，模型必须是固定的：

- 固定的特征清单；
- 固定的预处理方式；
- 固定的模型参数；
- 固定的训练窗口；
- 固定的模型文件；
- 固定的预测结果。

否则同一个策略版本今天跑和明天跑会得到不同结果，无法复现，也无法审计。

因此，每次回测都要绑定一个明确的 `model_id`，并记录：

- 模型文件 SHA256；
- 预测文件 SHA256；
- 训练数据版本；
- 因子构建版本；
- 代码版本；
- 随机种子和环境版本。

### 5.2 研究阶段：每次改动都是一个新版本

研究阶段会不断尝试新的特征、标签、窗口、超参数。每一次实质改动都应该产生新的模型版本，而不是覆盖旧版本。

建议至少记录：

| 字段 | 说明 |
|---|---|
| `model_id` | 唯一标识，例如 `lgbm_5d_20261019_ab12cd34` |
| `model_type` | `ridge`、`lightgbm` 等 |
| `label` | 例如 `fwd_ret_open_5` |
| `features` | 特征清单及其顺序 |
| `train_start` / `train_end` | 训练窗口 |
| `valid_start` / `valid_end` | 验证窗口 |
| `universe` | 股票池口径 |
| `preprocess` | 截面 rank、缺失填充、中性化方式 |
| `hyperparams` | 模型参数 |
| `seed` | 随机种子 |
| `data_version` | 数据库与因子版本 |
| `metrics` | 样本外 IC、Top-N 净收益、换手、回撤等 |

这样做的目的不是增加文档负担，而是保证任何一个历史结论都能追溯：当时用的是哪批数据、哪些因子、哪个模型、哪组参数。

### 5.3 生产阶段：滚动重训，但不是每天乱改

模型参数在训练完成后是固定的，但“模型”作为一个研究/生产系统，不是永远不变的。

原因很简单：

- 市场风格会变；
- 因子有效性会衰减；
- 交易者结构会变；
- 因子拥挤度会变；
- 数据分布会漂移；
- 原来的训练样本会逐渐过时。

所以生产中的常见做法是：

1. 按固定节奏重训，例如每季度或每月；
2. 用最近一段样本外数据验证；
3. 只有超过基线且通过稳定性检查，才提升为新版本；
4. 上线后持续监控，发现衰减就降权、停用或回滚。

重训频率本身也是策略设计的一部分，必须在回测前定好。不能先在测试集上试很多种重训频率，再挑一个最好的，那样会引入新的过拟合。

### 5.4 静态模型和滚动模型

两种做法要区分：

| 做法 | 训练方式 | 用途 | 风险 |
|---|---|---|---|
| 静态模型 | 用一段历史训练一次，之后不再更新 | 研究基线、快速验证 | 容易过时，不能代表生产 |
| 滚动模型 | 按固定节奏重训，每次只用当时可见的数据 | 更接近真实生产 | 实现复杂，重训规则也可能过拟合 |

第一版研究可以先用静态模型打通链路，但最终评估应该用 walk-forward 的滚动模型。否则回测结果会高估策略的长期生命力。

### 5.5 监控和淘汰

模型上线后，至少要监控：

- 预测分数的分布是否发生明显变化；
- 每日/每月 RankIC 是否持续衰减；
- Top-N 的净超额是否转负；
- 换手是否异常升高；
- 行业、市值、波动等暴露是否漂移；
- 特征缺失率是否变化；
- 回撤是否超过预设阈值。

可以预先定义停用条件，例如：

- 滚动 6 个月 RankIC 持续为负；
- 滚动 6 个月净超额低于某个阈值；
- 换手率超过历史均值的两倍；
- 特征分布漂移超过阈值；
- 回撤超过策略设计上限。

触发后不一定要立刻删除模型，可以先降权、暂停新开仓、回滚到上一版本，或者重新训练并观察。

### 5.6 一张表总结“什么会变，什么不变”

| 层面 | 是否固定 | 说明 |
|---|---|---|
| 单次回测中的模型文件 | 固定 | 保证可复现，绑定 `model_id` 和哈希 |
| 模型参数 | 训练后固定 | 不会再因为某一天的新数据自动改变 |
| 特征清单、标签、预处理 | 版本化 | 一旦改动就是新模型版本 |
| 训练窗口和重训频率 | 策略设计的一部分 | 必须在回测前确定 |
| 生产中的模型版本 | 定期更新 | 按季度/月度重训，验证后替换 |
| 组合构建规则 | 可以独立调整 | 不必和模型参数绑死 |

## 6. 在本项目中的落地位置

### 6.1 现有模块的分工

- `core/factors/` 和 `data/factors/`：提供因子值和因子定义；
- `md.fwd_return`：提供未来收益标签；
- `research/evaluation/calculate/`：提供 IC、分箱、换手、暴露等评估函数；
- `trading/backtest/signals.py`：当前的线性打分逻辑，是 ML 的替换点；
- `trading/backtest/strategies/`：目标权重 provider，是模型分数接入回测的边界；
- `trading/backtest/` 的执行层：负责 T+1、涨跌停、停牌、成本和账本。

### 6.2 建议新增的目录

```text
research/modeling/alpha/                         # 模型层代码
  dataset.py                   # 组装 X、y、mask、sample_weight
  preprocess.py                # 截面 rank/z-score、缺失处理、中性化
  split.py                     # purged walk-forward
  linear.py                    # Ridge / ElasticNet
  gbdt.py                      # LightGBM
  train.py                     # 训练入口
  predict.py                   # 预测入口
  evaluate.py                  # 样本外评估
  registry.py                  # 模型版本与产物管理

data/models/
  <model_id>/
    model.txt                  # 模型文件
    config.json                # 标签、特征、窗口、超参数
    features.json              # 特征清单与顺序
    metrics.json               # 样本外指标
    predictions/
      year=YYYY/part.parquet   # trade_date, stock_code, score
    manifest.json              # 数据版本、代码哈希、种子、依赖版本
```

`research/modeling/alpha/` 负责“学习和预测”，`data/models/` 负责“保存版本”，`trading/backtest/` 仍然只负责“组合和执行”。三层不要混在一起。

### 6.3 回测接入方式

推荐在 `trading/backtest/strategies/` 增加一个 `ml_rank` provider：

```text
输入：model_id、top_n、可选的换手/缓冲参数
读取：data/models/models/<model_id>/predictions
对齐：按回测日期和股票列 reindex
过滤：只用 eligible=True 的股票
输出：目标权重矩阵
```

这样现有的成本模型、涨跌停规则、T+1、行业约束、账本都不需要改。模型只负责给分数，provider 负责把分数变成权重。

正式接入时，运行快照要记录 `model_id`、模型文件哈希和预测文件哈希。否则同一个策略版本在不同时间跑，可能得到不同结果，无法审计。

### 6.4 三条不能破坏的约束

1. **时点性**：t 日的预测只能用 t 日收盘及以前可见的数据。标签、特征、行业、ST 状态、指数成分都要按当时的口径。
2. **可复现**：同一个 `model_id`、同一批数据、同一份代码，必须得到同一份预测。模型参数、特征顺序、随机种子、环境版本都要记录。
3. **样本外**：训练、验证、测试严格分开；重叠标签要 purge，测试集之后要 embargo；最终测试集不能反复调参。

这三条比模型选择更重要。违反任何一条，ML 的结果都不可信。

## 7. 如何判断 ML 是否真的有价值

### 7.1 先有基线

至少比较：

1. 单因子最强，例如 `MOM_20`；
2. 手工多因子线性组合，例如 `MOM_20 + EP_TTM - VOL_20`；
3. 全部因子等权 z-score 合成；
4. Ridge 或 ElasticNet；
5. LightGBM。

如果 LightGBM 打不过 Ridge 或线性组合，说明当前数据里没有足够的非线性/交互信息，或者模型过拟合了。这时候继续加复杂模型通常没有意义。

### 7.2 模型层指标

- 每日 RankIC 的均值和 ICIR；
- IC 的 t 统计量和胜率；
- 分 10 组的收益单调性；
- Top 10% 组合的超额；
- 预测分数的自相关和换手；
- 特征重要性的稳定性；
- 分年度、分市场状态的稳定性。

### 7.3 组合层指标

- Top-N 的净收益和净超额；
- 相对基准（如 H00300.CSI）的超额；
- 最大回撤；
- 换手率；
- 容量和成交参与率；
- 行业、市值、波动等暴露；
- 逐年、分市场状态的表现。

模型层 IC 高，不代表组合层一定好。A 股只能做多，Top-N 组合可能只用到分数头部，尾部的 IC 贡献对策略没有意义。所以最终一定要看扣费后的组合结果。

### 7.4 稳健性检查

- 换随机种子，结果是否稳定；
- 换训练窗口长度，结果是否稳定；
- 换调仓频率，结果是否稳定；
- 换股票池，例如全 A、沪深 300、中证 500、中证 1000；
- 换成本假设，结果是否仍然成立；
- 做特征消融，看看收益到底来自哪些因子；
- 做时间切片，看看收益是否只来自某一年；
- 记录所有试验，避免只报告最好的那一次。

如果模型只在某一个参数组合、某一段行情、某一个股票池里有效，它大概率不是稳定 alpha。

## 8. 常见误解

### 误解一：ML 会自动发现新因子

ML 主要是在已有特征上学习组合方式。它可以发现特征之间的交互，但不会凭空创造新的信息来源。新的财务数据、公告数据、另类数据、微观结构数据，仍然需要单独采集和构造。

### 误解二：模型训练一次就永远不变

模型参数在训练后固定，但模型版本会随着研究和市场变化迭代。生产中通常需要定期重训、监控和回滚。

### 误解三：特征重要性就是因子权重

特征重要性描述的是“模型在多大程度上使用了这个特征”，不是“应该给这个因子多少仓位”。树模型的 importance 还会受到特征尺度、相关性和分裂顺序的影响。

### 误解四：IC 高就是好模型

IC 高只说明预测值和未来收益在截面上有一定相关性。它不代表：

- 扣费后能赚钱；
- Top-N 表现好；
- 换手可接受；
- 容量足够；
- 在不同年份都稳定。

### 误解五：模型越复杂越好

模型越复杂，拟合能力越强，也越容易记住历史噪声。A 股的独立样本主要体现在时间维度，不是行数维度。复杂模型需要更强的正则化、更严格的样本外验证和更多的稳健性检查。

### 误解六：ML 可以替代回测和风控

ML 只是信号生成的一部分。组合约束、交易规则、成本、容量、风控和归因仍然需要独立实现。模型分数再好，如果买入涨停板、卖出跌停板、忽略停牌和成本，回测结果也不可信。

### 误解七：线性模型不算 ML

Ridge、ElasticNet 都是机器学习模型。真正要比较的是“简单模型”和“复杂模型”的样本外增量，而不是“有没有用 ML”这个标签。

## 9. 建议的推进顺序

### P0：固定基线

用现有回测跑出：

- 单因子最强；
- 手工多因子线性组合；
- 全部因子等权合成；
- Ridge。

同一区间、同一股票池、同一成本，记录净收益、超额、换手、回撤。这个结果是后面所有 ML 实验的对照组。

### P1：打通数据与线性模型

建立 `research/modeling/alpha/dataset.py`、`research/modeling/alpha/preprocess.py`、`research/modeling/alpha/split.py`，先跑 Ridge。目标是验证：

- 标签对齐是否正确；
- 特征是否有时点泄漏；
- walk-forward 是否按时间切分；
- 预测分数能否被 `calculate` 的指标函数评估；
- 结果能否复现。

### P2：LightGBM 滚动训练

在 P1 的管线上替换模型，做：

- 年度或季度重训；
- 3-5 个随机种子平均；
- 早停看验证集 RankIC；
- 和 Ridge、线性基线逐年对比；
- 特征重要性和消融分析。

### P3：接入回测

增加 `ml_rank` provider，读取预测面板，输出目标权重。检查：

- 扣费后的 Top-N 净收益；
- 换手和容量；
- 行业、市值、波动暴露；
- 与线性策略的差异来源。

### P4：稳健性和生产化

- 最终测试集；
- 多种子、多窗口、多股票池；
- deflated Sharpe 或类似的多次试验校正；
- 模型监控和重训流程；
- 版本登记、回滚和停用规则。

## 10. 一句话总结

ML 的价值，不是把因子公式换成一个不可解释的黑箱，而是把“如何组合因子”变成一个可验证、可迭代、可监控的预测问题。

它能不能留在策略里，最终只看一件事：

> 在严格的样本外、扣除交易成本、考虑换手和容量之后，它是否比简单的线性基线更稳定地创造超额收益。

如果答案是否定的，就应该诚实地继续使用线性模型。能证明“复杂模型没有增量”，本身也是量化研究的重要结论。
