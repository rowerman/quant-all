# ML 模型层模块架构

日期：2026-10-23

## 职责

ML 模型层把可见因子转换成截面预测分数。模型层不负责组合约束和交易执行；
下游通过标准预测产物使用模型结果。

```text
数据集与标签
    -> 预处理与时间切分
    -> 通用训练流水线
    -> ModelBackend
    -> 标准预测与 manifest
    -> 通用评估计划
    -> 通用评估执行器（经济门 + 组合风险门）
    -> 候选分数与风险时序
    -> 通用完整账本 / 最终留出
```

## 模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| 数据与标签 | 股票池、特征、未来收益标签 | 模型拟合 |
| 通用训练流水线 | 折循环、重拟合、产物写入、模型 ID | 具体算法内部训练 |
| 模型后端 | 单折拟合、早停或选参、预测、模型读写 | 组合构建、回测执行 |
| 评估计划 | 候选、参照、评分和持仓规则 | 具体模型装载 |
| 评估执行器 | 按来源计算分数、决策门、排序和产物 | 具体模型训练 |
| 风险门槛 | 目标组合的市值、流动性和行业主动暴露 | 交易执行和成本 |
| 通用账本入口 | 按评估 ID 执行候选并校验完整账本 | 选择候选或重算模型 |
| 回测 provider | 把标准预测转为目标权重 | 模型训练 |
| 最终留出 | 冻结输入、独立样本验收 | 调参和重新训练 |

## 扩展规则

1. 新模型实现 `ModelBackend` 并在后端模块导入时注册；后端目录自动发现，
   不修改共享折循环或固定后端清单。
2. 新模型必须输出 `trade_date`、`stock_code`、`score` 标准预测。
3. 模型专属分析留在后端或独立分析模块，不进入通用评估器。
4. 评估、回测和验收只通过 `model_id` 和标准产物定位模型。
5. 具体模型 ID 可以出现在文档示例和测试夹具中，不能成为主链路分支条件。
6. 历史 v1 manifest 只做读取归一化，不原地改写。
7. 模型来源、基线来源和融合来源都由评估计划声明，执行器不按模型类型分支。
8. 完整账本只读取评估产物中的候选分数，不重新平滑、融合或更换候选。
9. 模型索引只汇总训练事实和下游运行链接，不通过改写模型 manifest 表示评估状态。

## 模型生命周期

当前 Ridge 是回退模型，五种子 LightGBM 是已完成的实验主模型，单种子 LightGBM
已归档。直方图 GBDT `sklearn_hist_gbdt_label_rank_83e1200e554f` 已完成训练登记，
并已进入通用候选评估；当前模型不构成永久目标，新挑战者完成训练和独立验收后
即可替换。

2024-01-01～2026-10-15 已作为独立留出样本消耗并封存，不能用于新模型调参。
下个窗口登记为 2026-10-16～2027-10-15，当前数据尚未覆盖。
