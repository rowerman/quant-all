# 自动因子挖掘需求与口径

## 状态

本文件保留首版需求口径。截至 2026-11-01，S0～S9 已交付并完成验收，M1～M5
已实施并通过 V135 路线图审计。当前 V1 是默认生产链路；V2 证据驱动搜索和 M5
隔离代码沙箱均需显式启用，V2 候选可通过监测站页面审批、整批正式发布和失败重试。

后续任务不在本文件中继续累加，统一记录在
[`FACTOR_MINING_PROGRESS.md`](../../../FACTOR_MINING_PROGRESS.md)。

## 目标

用户提交一段研究假设后，系统调用受控的 RD-Agent Worker 生成候选因子表达式，对候选
执行技术校验、快速筛选和完整评估，在监测站展示结果与风险提示，最后由用户人工决定
批准或拒绝。首版只证明挖掘模块自身可用，不宣称独立样本发现或生产可用性。

用户流程：

```text
提交研究假设
  -> 生成候选
  -> 字段与算子校验
  -> 快速筛选
  -> 完整评估
  -> 候选冻结
  -> 模块测试段一次性验收
  -> Web 审核
  -> 人工批准 / 拒绝
```

首版不自动批准、不自动重训模型、不自动生成策略或回测。自由探索和资料驱动只保留扩展
接口，不进入首版验收；两项仍未实现，已列入后续进度记录的 P3 和 P2。

## 数据口径

数据版本为 `tushare_fullA_20000104_20261015`，行情覆盖
2000-01-04～2026-10-15，共 6488 个交易日。主口径沿用现有模型研究契约。

| 项目 | 冻结口径 |
|---|---|
| 股票池 | `all_a`：`can_buy_close`、非 ST、上市满 60 个自然日，保留历史退市股票 |
| 主标签 | `fwd_ret_open_5`，t 日决策、次一交易日开盘起算未来 5 个交易日 |
| 价格 | 因子计算使用后复权价；标签使用库内预计算的开盘通道未来收益 |
| 停牌 | t 日停牌不进入信号池且标签为空；持有期内停牌价格按上一有效交易日价格填平 |
| 分组 | 每日截面按平均名次分 10 组 |
| IC | Pearson IC 使用 3 倍 MAD 去极值，RankIC 对原始有效配对排名 |
| 存储精度 | 因子值落 float32；落盘前非有限值转为空 |

| 用途 | 区间 |
|---|---|
| 历史预热 | 2000-01-04～2011-12-31 |
| Agent 研究与候选快速筛选 | 2012-01-01～2025-10-15 |
| 完整评估 | 2020-01-01～2025-10-15 |
| 模块测试段 | 2025-10-16～2026-10-15 |

模块测试段已被模型模块的最终留出验证使用。本项目首版只关心挖掘模块内部逻辑，因此接受
这段期间的数据重叠；测试结论只能写“模块隔离验收”，不能写“全项目盲测”或“独立样本
发现”。测试段只在候选冻结且技术门禁通过后使用一次，结果不得进入 Agent 反馈、候选
重排或再次生成。

## 物理隔离

```text
候选运行
  data/databases/factor_mining.duckdb
  data/factor_mining/runs/<run_id>/
  data/factor_mining/cache/

正式因子（候选阶段只读）
  data/factors/<family>/year=YYYY/part.parquet
  data/databases/factors.duckdb
```

候选数据库、候选 Parquet 和评估缓存不得写入正式因子路径。只有 S8 的人工审批、
暂存构建、全量校验和原子发布全部成功后，候选才能进入正式因子库。V88 归档中的
`factor_mining.duckdb` 和候选目录不是当前数据基线。

运行日志写入 `logs/research/mining/`，按模块、运行和阶段记录状态变化，但不得记录
Key、完整请求头或敏感原文。

## 人工审批

首版是单用户本地审批，不建设多角色权限系统。批准时用户必须看到并核对候选哈希与关键
质量结论，填写审核备注；拒绝同样必须填写原因。

审批不设时间有效期，但下列任一内容变化都会使原审批失效：

- 候选表达式、语义哈希或依赖字段；
- 行情数据快照、标签口径或时间切分；
- 字段目录、算子目录或表达式规则；
- 技术门禁、快速筛选或完整评估结果；
- 模块测试段领取状态。

失效候选必须重新评估；不得沿用旧审批直接发布。

## Worker 与密钥

| 项目 | 固定值 |
|---|---|
| RD-Agent | `1.0.0` |
| Worker Python | 3.11，独立镜像与主项目 Python 3.12 隔离 |
| LLM 接口 | DeepSeek 的 OpenAI 兼容接口 |
| 默认模型配置 | `deepseek/deepseek-chat`，可由 Worker 配置覆盖并在运行记录中固定 |
| 默认轮次 | 3 |
| 默认候选数 | 12 |
| 默认完整评估数 | 4 |
| 默认 LLM 调用上限 | 30 |

预算参数放在配置文件中，允许按任务覆盖，但每次运行必须冻结实际取值并写入事件记录。
Worker 不可用时明确失败，不静默回退到 Mock 或旧候选。

DeepSeek Key 只从 Worker 环境读取。浏览器、主服务、候选数据库、日志、截图和
`AiRecord/evidence/` 均不得保存 Key。真实 Key 不写入示例配置或版本记录。

## 阶段约束

- 每阶段结束必须单独验收，未验收不得进入下一阶段。
- 用户只要求设计时，不创建或修改实现代码。
- S1 后的正式因子库和活动代码是后续基线；V88 归档只作参考，不能直接续写。
- S2 先冻结契约、状态机、幂等、并发和回滚规则，S3 再冻结字段目录与 DSL。
- 候选评估复用现有因子口径；正式与临时路径必须通过全指标一致性测试。
- 所有模块、函数和跨模块流程都必须有对应测试；日志、错误码、文档和版本记录同步更新。
