# 风格拆分：7 个 Barra 近似风格因子

## 为什么要做

IC 高不代表这个因子「自己」有用：它可能只是替规模、动量这些风格打工。
风格拆分回答两件事：

1. **暴露**：这个因子在哪些风格上有系统性下注，下注有多重（系数与 t 值）；
2. **增量 IC**：把风格解释掉之后，还剩多少选股能力（残差的 RankIC）。

实现分两块：`research/evaluation/calculate/styles.py` 负责按 SQL 算出风格**原始值**，
`research/evaluation/calculate/exposure.py` 负责在同一个回归样本上标准化、逐日回归、算残差。

风格 SQL 在 DuckDB 内用整数编码输出股票，pandas 再还原为类别列，避免转换数百万行重复
字符串；`build_styles(..., compact=False)` 的公开默认仍返回原有 object 股票列，
`EvalContext.styles()` 内部使用紧凑类别列。窗口查询使用 4 个 DuckDB 线程。暴露阶段把
8 个原始风格列和因子一次取成连续矩阵，经多列 C++ 融合 MAD/z-score 核处理，并复用同一
稳定日序与 offsets。V119 起逐日 OLS 默认走 C++，业务一致性门槛为 `1e-5`；病态矩阵
按日回退 Python。

## 7 个风格因子

窗口按**有效交易日**推进（`status = 'trading'`，停牌不占窗口），与数据项目的因子构建口径一致。
取值算到评估区间结束为止；为了拿到 `t-250` 的收盘价，取数从区间起始日往前回溯 260 个交易日
（`STYLE_LOOKBACK_DAYS`）。长期停牌股会另外补足评估起点前的 250 次有效交易，
保证同一天的风格值不随评估区间起点改变。

| 风格 | 定义 | 最小观测 | 说明 |
|---|---|---|---|
| SIZE | `ln(total_mv)` | 当日有市值 | 总市值（万元）取对数，越大取值越大 |
| VALUE | `z(1/pb)` 与 `z(1/pe_ttm)` 的均值 | 至少一个为正 | pb / pe_ttm 非正视为缺失；缺一个就用另一个 |
| MOMENTUM | `close[t-20] / close[t-250] - 1` | 窗口内 ≥ 251 个有效交易日 | 12 个月动量、跳过最近 1 个月 |
| SHORT_REV | `1 - close[t] / close[t-20]` | ≥ 21 个有效交易日 | 最近 1 个月收益的反向 |
| VOL | `std(ret, 60)` | ≥ 40 个有效交易日 | 日收益标准差（未年化） |
| LIQUIDITY | `mean(turnover_rate, 20)` | ≥ 15 个有效交易日 | 平均换手率，越大越活跃 |
| BETA_60 | `regr_slope(ret, idx_ret_300, 60)` | ≥ 40 个有效配对日 | 基准沪深300（`000300.SH`），与库里已实现的 `BETA_60` 因子同基准 |

`close` / `ret` 一律用后复权表 `md.daily_hfq`；`total_mv` / `turnover_rate` / `pe_ttm` / `pb`
同表取。指数收益用 `md.index_daily.pct_chg / 100`，缺这张表直接报 `EVAL-302`
（BETA_60 算不出来，不会静默给空值）。

## 标准化与缺失

- 回归样本 = **池内且因子非空**（不看标签），这样暴露与标签周期解耦；
- 因子与风格都在**同一批样本**上逐日做「3 倍 MAD 去极值 + z-score」，
  保证系数含义统一为「因子每 1 个标准差的风格暴露」；
- 风格算不出来的样本标准化后**置 0**，这是“中性填补”的建模假设，不能理解为真实没有暴露。
  这些股票照常参与回归；若某风格整日都缺失或恒定，该系数不可估计，返回 NaN，
  当天仍可用其他可估计风格回归。剩余风格完全共线时整日跳过；
- z-score 是单调线性变换；此前的 MAD 裁剪可能制造并列名次，不能笼统说整套预处理不改变秩。
  对照 raw 使用原始因子，residual 使用裁剪与标准化后的回归残差，两者是处理前后的结果对照。
- VALUE 是两个 z 的均值，不保证单位方差；缺失置零也会改变最终方差。
  系数含义是“该风格增加 1 单位时，标准化因子的变化”，不能把所有系数当作严格相同尺度。

## 暴露与增量 IC

- 逐日截面 OLS（Fama-MacBeth）：`标准化因子 ~ 1 + 7 个标准化风格`；
- 每个风格报：系数时序均值、**Fama-MacBeth t**（日度系数序列的均值 / 标准误）、
  `positive_share`、`significant_share`（|日度 t| > 1.96 的占比）、天数；
- 同时给出逐日系数序列与逐日 R²，前端可以直接画线；
- 单日样本 < 30 只、因子恒定/响应非有限、剩余设计矩阵秩亏时整日跳过。
  回归用删除不可估计风格后的列数判断自由度；有效回归日 < 20 天只报「样本不足」。
  回归系数的 t 值与 Fama-MacBeth 时序 t 都是普通标准误，未做 HAC 修正；自相关时只作参考。
- **增量 IC** = 残差与标签的逐日 RankIC。对照 raw 在残差表的同一批有效配对上重算，
  并只使用残差 IC 有定义的日期，因而不保证等于 overview 的原始 RankIC。
  `delta = raw - residual` 仅为处理前后对照差值，不是严格可加的风格贡献。
  `survivor_share = residual/raw` 是 IC 均值之比，不是解释率，可超出 [0,1]；raw 近零时不稳定。

## 行业层（默认关闭）

`IndustrySource` 是行业数据源的协议（`key` / `label` / `note` / `load(conn)`），
已注册的静态实现是 `StockBasicIndustry`，读 `ref.stock_basic.industry`。

指标参数 `industry` 取值 `off`（默认）或已注册的行业源键；开启后设计矩阵加上行业哑变量
（丢掉第一类，避免与截距共线），payload 里回报行业数、覆盖率与缺失占比。

**为什么默认关闭**：`ref.stock_basic.industry` 是**静态快照**——
用今天的行业去解释历史（无法反映行业变更）、退市股不在表里、与中证/申万行业口径也不一致。
要真正做时点行业，得先补 `ref.industry_member`（Tushare 的行业成分历史）与申万成分，
这件事记在 `docs/core/factors/missing_data.md` 的数据缺口里。

## 读法

- 某个风格上系数大且 t 显著 → 这个因子主要是那个风格的代理，
  选股能力可能被风格解释掉；
- 残差 IC 明显低于原始 IC → 之前看到的 IC 有相当一部分来自风格暴露；
- 残差 IC 与原始 IC 接近（`survivor_share` 接近 1）→ 信号基本独立于这 7 个风格；
- 注意：暴露是逐日截面回归的时序均值，和 IC 一样受样本区间影响，换区间结论会变。

一个已知的「看起来吓人、其实正确」的结果：`SHORT_REV` 定义为 20 日收益的反向，
所以 20 日动量类因子（例如库里的 `MOM_20` = `close/close[t-20] - 1`）在它上面的暴露
正好是 **-1**、其它风格接近 0，残差在数值容差内会被明确置零，此时残差 RankIC **无定义**（而不是可测的 0）。这说明该因子本身就是「短期反转」
这个风格的代理，不是拆分算错了。
