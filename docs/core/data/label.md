# 标签模块（md.fwd_return）

## 负责功能

把「t 日收盘后能拿到的信息」和「t 之后真实发生的收益」对齐成监督学习的目标 y。
第④⑤⑥步共用同一张表：因子 IC、分层、衰减、LightGBM 的训练目标都取这里。

## 口径

决策时点统一是 **t 日收盘后**，N 取 1 / 3 / 5 / 10 / 15 / 20，单位是交易日。
两套成交通道都产出，列名带标记区分：

| 列 | 买入 | 卖出 | 说明 |
|---|---|---|---|
| `fwd_ret_close_N` | t 日收盘价 | t+N 日收盘价 | 对应归档项目说明里的公式，执行上按尾盘集合竞价成交理解 |
| `fwd_ret_open_N` | t+1 日开盘价 | t+1+N 日开盘价 | 更贴近 T+1 制度；持有交易日数与收盘通道一致，两套结果可直接对比 |

价格一律用后复权（`md.daily_hfq`）。停牌段用**上一有效交易日价格填平**
（`last_value(... IGNORE NULLS)`），复牌跳空在终点价一次性计入，
得到的是真实持有期收益，而不是「停牌就当没涨」的假数据。

## 缺失规则

| 情形 | 标签 |
|---|---|
| t 日停牌 | 12 个标签列全为空（当天不是可建仓的决策点） |
| t+N（开盘通道 t+1+N）超过该股最后一行 | 为空（尾部天然不足） |
| 其余交易日行 | 有值 |

行集与 `md.daily_hfq` 完全一致（17,999,882 行），键同样是 `stock_code` + `trade_date`，
可以直接 join。表里**不筛股票池、不带可交易性标记**：池子与「买不买得进」属于下游，
按需 join 日线表的 `can_buy_close` / `can_buy_open_next` / `can_sell_*`。

## 生成与自检

```bash
.venv/bin/python -m scripts.build_db.build      # 建库时自动生成并自检
.venv/bin/python -m scripts.build_db.labels     # 在已有库上只重建标签并自检
```

生成是一条 DuckDB 窗口 SQL（`core/data/scripts/build_db/labels.py`），全表 1795 万行约 4 秒。

> 注意：单独跑 `labels` 是 `CREATE OR REPLACE`，DuckDB 不会回收旧数据块，库文件会变大
> （实测从 7.2 GB 涨到 8.7 GB）。想要紧凑文件就重跑一次完整建库，`build` 是删库重建。

自检项（`verify_labels`，任一项不过就按建库失败处理）：

1. 行数等于 `md.daily_hfq`；
2. 停牌行（586,360 行）12 个标签列全空；
3. 每档标签在交易日行上的缺失数 == 该档尾部应有的缺失数；
4. 与 `md.daily_hfq.ret` 错位比较，差异超过 `1e-4` 的占比 < 0.5%：
   实测 26,837 行（0.1545%），正好是清洗阶段 A3 的 28,715 行减去 1,878 行停牌行
   （停牌行没有标签，不进比较）；
5. 没有标签小于 -100%（做多不可能亏掉超过本金），也没有绝对值超过 2000%
   （实测最大 1042%，来自 BJ920799 2024 年 10 月的连续暴涨，是真实行情）。

## 读取

```python
import quant

# 长表：按需取若干档
lab = quant.load_label(start="2024-01-01", end="2024-12-31",
                       horizons=[1, 5, 20], price="close", stocks=["SH600000"])

# 宽表：交易日 × 股票，直接和因子做截面运算
fwd5 = quant.load_label_wide(5, start="2024-01-01", end="2024-12-31", price="close")
```

## 常见坑

1. 别用前复权算标签：`qfq` 的基准是该股最后一个交易日的因子，价格水平含未来信息
   （收益序列本身是干净的，但没必要冒这个险）。
2. `shift` 方向：`ret.shift(-1)` 才是未来一日收益，`shift(1)` 是过去。
3. 停牌行不能当普通行用，必须显式置空。
4. 训练/验证切分点前后要留 N 天空档，否则标签跨过切分点会造成泄漏。

## 修改时注意

1. `core/data/quant/schema.py` 的 `LABEL_HORIZONS` / `LABEL_PRICES` 是唯一口径来源，
   建库与读取层都从这里取，不要在别处另写一份；
2. DuckDB 里 `close` / `open` 是保留字，SQL 里派生列别名必须写 `AS px_close` 这种名字；
3. 改口径要同步更新 `meta.data_dictionary`、本文件与 `README.md`。
