# 因子口径与算子语义

## 行集与缺失

1. 因子文件的行集与 `md.daily_hfq` **完全一致**：包含停牌行、含退市股，不多不少。
   自检里的行集检查会双向比对，任一侧有差异都算不通过。
2. 停牌行的因子值**一律为空**。原因很直接：停牌行本身没有行情与估值
   （`md.daily_hfq` 里 586,360 行停牌记录的四价、成交额、估值列全为空），
   与 `md.fwd_return` 的标签口径一致。下游要按可交易性过滤，用
   `can_buy_close` / `can_sell_close` 这些标记列。
3. 计算时先把 `status = 'trading'` 的行筛出来，窗口只在这些有效交易日上推进，
   停牌不占窗口；算完再左连接回完整行集，于是停牌行自然是空值。
4. 历史不足时结果为空，不做填充、不做插补。次新股的前 60 个交易日没有 60 日动量，
   这是正常的。

## 价格与单位

1. 价格类因子一律用后复权价（`md.daily_hfq`）：动量、波动、技术形态都建立在复权价上，
   除权日不会出现假跳空；
2. 换手率、估值、市值、涨跌停标记直接用库内列（`turnover_rate`、`pe_ttm`、`total_mv`…），
   它们本身不受复权影响；
3. 单位沿用主库口径：`amount_cny` 是元、`total_mv` 是万元、`turnover_rate` 是百分数。
   例如 Amihud 因子写成 `|ret| / (amount / 1e8)`，即「每亿元成交额带来的绝对收益」。

## 财务数据时点

1. 财务因子通过 `fin.*` 表读取，源定义在 `core/factors/sources.py`；
2. 公告可用日取 `coalesce(f_ann_date, ann_date)`，连接条件为
   `trade_date > available_date`，公告日次一交易日起才可见；
3. 同一 `(stock_code, available_date)` 有多期报告时取最新报告期和更高 `update_flag`；
4. 财务百分数在因子层统一除以 100，极端值按因子定义中的区间置空，不做跨股票截尾。

## 跨年窗口

构建是逐族逐年的，但**因子值不依赖「按年切块」**，这是靠输入层的取法保证的。
每年计算时的输入由两段拼成：

1. **全局回看区间**：从当年年初往前数「最长回看窗口 + 5」个交易日开始，到年末为止的
   全部有效交易日。这一段必须按全局交易日取，因为截面算子（`cs_rank` 之类）
   需要每个交易日的完整横截面；
2. **每只股票在年初之前的最近「最长回看窗口 + 5」个交易日**：让停牌大半年的股票
   也有足够历史，否则它会在年初被算成空值——因子值不该因为切块而变。

两段合起来，既保证横截面完整，也保证任何个股的窗口都取得到。回看窗口由
`FactorSpec.lookback` 决定，留空时按表达式自动推导，推导值不足会直接报错。
自检里的前视检查会在抽样日期上用同一套取法重算并逐行比对，
等价于一次「分块无关性」检验。

## 精度与非有限值

1. 因子值落盘为 float32（实测 zstd 压缩后约 3.3~3.9 字节/值，100 个因子全历史约 6~7GB），
   中间层保持 double；
2. 落盘前统一做 `isfinite` 检查，`NaN` 与 `inf` 一律转成空值。常收益序列的
   `corr` 会算出 NaN、除零可能算出 inf，这两种情况在真实数据里都出现过
   （例如 `PV_CORR_20` 在 2024 年就有），所以放在构建层统一处理，而不是逐因子写 if。

## 算子语义

`core/factors/ops.py` 里的时序算子统一按 `stock_code` 分组、`trade_date` 排序，
窗口长度按行数计（行＝有效交易日）：

| 算子 | 语义 | 备注 |
|---|---|---|
| `ts_delay(col, n)` | n 个交易日前取值 | `lag` |
| `ts_delta(col, n)` | 与 n 日前之差 | |
| `ts_mean / ts_sum / ts_min / ts_max / ts_median` | n 日聚合 | 跳过空值 |
| `ts_std(col, n)` | n 日标准差 | 默认样本标准差，窗口内不足 2 个值返回空 |
| `ts_skew / ts_kurt` | n 日偏度 / 峰度 | DuckDB 的总体口径 |
| `ts_corr / ts_cov / ts_slope / ts_r2` | n 日相关 / 协方差 / 回归斜率 / 决定系数 | 回归类因子建议加最少观测数保护 |
| `ts_std_downside` | 下行波动 | 只把负值计入 |
| `ts_rank(col, n)` | 当前值在最近 n 日中的分位 | 见下方说明 |
| `ts_row_number / ts_arg_max` | 行号与「极值所在行号」 | 多层写法用 |
| `cs_rank / cs_zscore / cs_demean / cs_scale` | 截面分位 / 标准化 / 去均值 / 归一 | 按 `trade_date` 分组 |
| `signed_power / safe_div / neg` | 保号幂 / 安全除法 / 取负 | |

### ts_rank 为什么不用 percent_rank

SQL 标准规定 `rank()`、`percent_rank()` 这类排名函数**忽略窗口帧**，
DuckDB 也遵守这一点：`percent_rank() over (... rows between 4 preceding and current row)`
算出来的是「全历史分位」，不是「最近 5 日分位」。

所以 `ts_rank` 用 n-1 次 `lag` 比较实现：分子是最近 n-1 个交易日里
小于等于当前值的个数（并列计在一起），分母固定为 n-1，前值缺失不计入。
数值范围 0~1，语义清晰且可复现。

### 需要多层写法的因子

`EMA`、`MACD`、`SMA(X, n, m)`、`DECAYLINEAR`、`REGBETA` 这类递归或需要中间列的公式，
用 `layers` 写多层即可：每层只写一个表达式，结果依次叫 `v1`、`v2`…，
最后一层就是因子值。两个现成的模板：

- `ALPHA101_001`：行号层 → 波动率层 → 幂变换层 → `arg_max` 层 → 截面排序层；
- `GTJA_191_001`：日内涨跌幅层 → 成交量变化层 → 两个截面分位层 → 6 日相关层。

写多层时注意：DuckDB 不允许「聚合函数里再套窗口函数」，
所以嵌套的窗口函数必须拆到不同层，用 `v1`、`v2` 传递。

## 已知限制

1. **行业与板块**：V44 已入库 `ref.sw_industry_member` 的 SW2014/SW2021 时点区间；新实现应按交易日
   做时点连接，不能继续使用 `ref.stock_basic.industry` 静态快照。因子评估链目前尚未接入该表，
   见 `missing_data.md`。
2. **基本面因子**：V46 已接入四张 `fin.*` 表和 18 个财务因子；预告、快报、概念板块仍未入库。
3. **市场类因子**：`RS_20`、`BETA_60` 用沪深300 做基准，2002-01-04 之前为空；
   回归类因子加了「窗口内至少 40 个交易日」的保护，否则次新股开板后两三个点会算出上千的伪贝塔。
4. **复现类因子**：Alpha101 / GTJA191 的公式以公开原始表为准，
   本项目的实现口径写在每个因子的 `formula` 字段里；两者不一致时以本文件与
   `core/factors/alpha101.py`、`core/factors/gtja191.py` 的注释为准。
