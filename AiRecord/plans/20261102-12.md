# 20261102-12 持久化 V3 运行恢复状态

- 日期：2026-11-02
- 版本：V163
- 类型：fix
- 进度任务：P5-01

## 目标

让 V3 只依赖 `mining_v3` 和 `mining_v3.runtime_*` 持久化事实恢复中断运行，覆盖手工
假设、自由探索、资料驱动和 CoSTEER 四类来源。服务重启后必须重验输入、上下文、来源、
候选包络和既有审批，只继续未完成步骤，不重复付费 Worker 调用。

## 设计

1. 新增 V3 运行时可恢复状态结构，统一读取请求、冻结上下文、输入包络、资料输入和
   CoSTEER 预置候选。
2. 新增 `mining_v3.runtime_seed_candidate` 表，创建 CoSTEER 运行时幂等保存候选及
   来源绑定；已记录候选的旧运行可从 V3 候选包络回退读取。
3. 配置 V3 运行时先持久化输入和上下文；创建、候选同步和搜索编排不再依赖进程内
   `_run_inputs`、`_run_contexts`、`_run_requests` 或 `_run_seed_candidates` 字典。
4. 恢复前校验运行请求、上下文、输入、资料摘要、种子、全部候选证据和审批有效性，
   任不一致时抛出 `MINING-165` 且不修改运行状态。
5. V3 启动时把遗留 `queued` 和活动阶段标为 `interrupted`，显式恢复回原状态；V2
   启动接管范围保持原样。
6. 为四类来源增加关闭服务、重建存储后恢复的联合测试，并覆盖篡改拒绝和 V2 兼容。

## 验收

- 四类来源均可从中断或遗留 `queued` 状态恢复并完成原有验证链路。
- 已完成的 Worker 轮次、资料抽取和转换不会再次执行。
- CoSTEER 重启后仍保留预置候选且不调用搜索 Worker。
- 恢复事实被篡改时运行状态不变，并返回稳定错误码 `MINING-165`。
- V1/V2 运行语义、HTTP 路由和既有完成态 V3 数据保持兼容。

## 验证

- V3 core、状态机、V3 API 和 V2 恢复定向回归。
- `compileall`、`git diff --check`。
