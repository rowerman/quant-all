# 20261102-1 P3-01 自由探索输入契约

## 目标

完成 `FACTOR_MINING_PROGRESS.md` 的 P3-01，为 V2 搜索运行请求增加 `hypothesis` 和
`free_exploration` 两种输入模式，保持旧请求兼容，并确保两种模式都有稳定请求哈希。

## 范围

- 扩展 `SearchRunRequest`，增加输入模式和可空假设。
- 定义模式、假设缺失或混入时的严格校验。
- 兼容缺少输入模式的旧请求字典和既有请求哈希。
- 让 V2 存储可以保存自由探索请求，同时保持现有表结构。
- 不在本轮实现初始方向生成、Web 模式选择、页面预算展示或完整自由探索运行。

## 接口设计

1. `hypothesis` 模式：默认模式，必须提供 8～4000 字假设。
2. `free_exploration` 模式：假设必须为 `None`，预算和模型配置继续按现有契约校验。
3. 旧请求未提供 `input_mode` 时按 `hypothesis` 解析。
4. `hypothesis` 模式的请求哈希沿用旧算法；自由探索显式纳入 `input_mode` 和空假设。
5. 数据库展示字段对自由探索使用固定标签“自由探索”，原始请求 JSON 保存真实模式。

## 实施步骤

1. 在搜索契约类型中增加模式常量和校验工具。
2. 修改 `SearchRunRequest` 的构造、序列化、反序列化和稳定哈希。
3. 调整 V2 运行存储的展示假设写入，不修改表结构。
4. 增加契约、存储和 API 兼容测试。
5. 更新挖掘契约、V2 搜索、Web 和项目指南文档。
6. 更新进度、版本、变更和差异记录，运行定向测试后提交。

## 验收

- 旧位置参数、关键字参数和缺少 `input_mode` 的持久化字典继续可用。
- 两种合法模式生成稳定且可区分的请求哈希。
- 非法模式、空假设和自由探索混入假设均被拒绝。
- 自由探索请求可写入现有 V2 存储，读取后仍可识别模式。
- 现有 V2 API 旧请求回归通过。

## 风险

- 自由探索执行仍未实现；本轮只交付可审计的请求和安全持久化边界。
- 请求哈希兼容需要保留旧字段集合，不能用简单追加字段改变历史请求身份。
