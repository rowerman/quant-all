# 20261102-8 P4-03：V3 审核、审批与共享发布闭环

- 日期：2026-11-02
- 版本：V159
- 类型：feat
- 进度任务：P4-03

## 目标

让四类 V3 来源经同一审核资格、人工最终审批和共享正式发布链路进入现有因子目录。
V3 只新增自己的上下文、审批和候选状态事实，正式发布继续写共享
`mining.publication*`，不建立第二套发布器。

## 设计项

1. P4-03.1：登记并校验 V3 冻结搜索上下文，发布时确定性转换为现有
   `FrozenContext`。
2. P4-03.2：新增 V3 候选审核摘要；五个阶段必须全部存在且通过。
3. P4-03.3：新增单一来源最终审批、幂等/冲突校验、候选状态和审计事件。
4. P4-03.4：让 `MiningV3Store` 实现共享发布服务接口，支持整批发布、恢复、失败重试
   和证据变化阻断。
5. P4-03.5：保留 V3 候选包络及来源哈希到正式定义清单，并完成下游联合验收。
6. P4-03.6：完成版本、进度、模块文档、变更、差异和独立提交。

## 决策

- 同一候选可以绑定多个来源，但只能选择一个来源形成最终批准或拒绝；其他来源继续
  作为审计记录。
- 审批按 `(run_id, candidate_id)` 唯一，证据或来源变化会使已有审批失效。
- 发布批次来源固定为 `v3_research`，批次必须覆盖运行内全部已批准候选。
- P4-03 只提供后端存储和服务接口，不开放新页面，不实现运行编排或旧库迁移。
- 用户已有的 `.gitignore` 和 TODO 文档迁移不进入本轮提交。

## 验收

1. 四类来源都能通过相同审核资格和人工审批接口。
2. 缺失或失败证据、上下文变化、候选/来源/证据篡改均阻止审批或发布。
3. 共享发布成功、失败重试、并发启动和进程恢复测试通过。
4. V3 正式因子可被因子读取、评估、模型特征和回测解析。
5. V1/V2 审批、发布和下游回归不受影响。
6. 定向测试、Python 编译和 `git diff --check` 通过，任务文件单独提交。
