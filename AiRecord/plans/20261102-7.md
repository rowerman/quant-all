# 20261102-7 P4-02：统一 V3 输入、候选与来源绑定

- 日期：2026-11-02
- 版本：V158
- 类型：feat
- 进度任务：P4-02

## 目标

让手工假设、自由探索、资料驱动和 CoSTEER 四类来源生成统一的 V3 输入、候选、
证据和来源绑定，并建立只保存白名单身份与哈希的 `mining_v3` 存储。V2 现有运行、
审批、发布和资料链保持兼容。

## 设计项

1. P4-02.1：新增 V3 来源适配模块，为四类来源构造稳定运行 ID、来源 ID、
   `ResearchInputEnvelope` 和 `ResearchSourceReference`。
2. P4-02.2：资料候选进入 V3 前移除 V2 专用的来源参数，候选 ID、内容哈希和语义
   哈希不因资料或沙箱来源变化。
3. P4-02.3：新增五阶段 V3 证据适配器，严格校验候选、评估、输入和证据身份。
4. P4-02.4：新增 `mining_v3` schema 和事务化存储，保存输入、来源、候选来源及
   评估证据引用；同一候选允许绑定多个来源。
5. P4-02.5：完成四类来源联合测试、旧库拒绝、幂等与冲突测试、文档、版本、进度、
   变更、差异和提交记录。

## 决策

- V3 存储只在全新数据库初始化；检测到 V1/V2 时拒绝自动迁移。
- 来源身份与候选身份分离，来源绑定通过独立记录完成。
- 报告正文、Prompt、沙箱源码、密钥和主机路径不进入 V3 公开存储。
- V3 审批、发布、运行编排、Web、自动迁移和真实 Worker 调用不在本轮范围。

## 验收

1. 四类来源可产生同一候选契约，同一候选保持相同 ID 和内容哈希。
2. 来源变化改变来源引用、候选包络和审批证据哈希。
3. `mining_v3` 写入幂等、冲突可识别，证据可完整回读。
4. 新测试、相关契约回归、项目布局和静态检查通过。
5. 任务文件单独提交，不包含用户已有的 `.gitignore` 和 `TODO_docs` 改动。
