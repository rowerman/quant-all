# 20261102-6 P4-01：冻结 V3 研究闭环设计

- 日期：2026-11-02
- 版本：V157
- 类型：feat
- 进度任务：P4-01

## 目标

冻结 V3 的版本号、四类研究来源、候选与证据绑定方式、运行状态门面、目标存储范围和
V1/V2 兼容策略。本轮只形成可执行公共契约与设计文档，不接入运行、审批、发布、Web
或真实迁移。

## 设计项

1. P4-01.1：新增 `mining.v3_contracts`，定义 `mining_v3` 存储版本、`researchrun_`
   运行前缀、四类输入模式和 V3 发布来源。
2. P4-01.2：新增严格来源、输入、证据和候选包络类型。候选内容哈希和候选 ID 保持
   来源无关；来源、证据和候选通过包络及审核摘要绑定。
3. P4-01.3：新增 V3 状态门面，复用 V1/V2 已有的运行、候选和发布状态机，不复制状态表。
4. P4-01.4：新增 `docs/research/mining/v3-integration.md`，说明四类来源的数据流、
   `mining_v3` 存储范围、共享发布事实、显式迁移和禁止边界。
5. P4-01.5：补齐公共导出、单元测试、版本/进度/变更/差异记录和定向回归。

## 决策

- V3 使用新的 `mining_v3` schema，V1 `mining` 和 V2 `mining_v2` 保留为旧数据只读来源。
- V3 候选与分阶段证据继续使用 V2 的受控 DSL、冻结窗口和尝试台账语义。
- 正式审批与原子发布继续写共享 `mining.publication*`，V3 批次来源为
  `v3_research`。
- CoSTEER 沙箱只提供已封存产物和人工提升证据；导入 V3 前必须重新形成受控 DSL
  候选，并重新完成五阶段证据。
- 普通启动不得把 V1/V2 静默迁移为 V3；迁移由 P4-04 以显式、事务化方式实现。

## 验收

1. 四类来源和未知模式均有严格解析测试。
2. 来源变化不改变候选内容哈希或候选 ID，但改变输入/候选包络哈希。
3. 候选、来源或证据任一变化会改变 V3 审核摘要输入。
4. V3 状态门面与现有状态机逐项一致，中断、取消、过期和终态规则不变。
5. 定向测试、导入检查、`git diff --check` 和文档引用检查通过。

## 边界

- 不创建 `mining_v3` 数据库表，不修改 `MiningV2Store`、Worker 协议、API、页面或发布服务。
- 不执行迁移、不调用真实 Worker、不写正式因子。
- 用户已有的 `.gitignore` 和 `TODO_docs` 迁移不纳入本提交。
