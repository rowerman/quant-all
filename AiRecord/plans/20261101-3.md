# 20261101-3 计划：实现 V2 候选审批状态与证据哈希

- 日期：2026-11-01
- 版本：V138
- 类型：feat
- 进度任务：P0-02

## 目标

为 V2 审核态候选增加可重算的审批资格、审批证据哈希和最终审批记录，使候选能在
`review_ready -> approved/rejected` 之间原子迁移。V2 运行继续停在 `review_ready`，
本轮不接入正式发布、API 或页面。

## 实现

1. 在 `mining_v2` 增加追加式 `search_approval` 表，一个候选只允许一条最终审批。
2. 新增审批资格和证据摘要契约；证据哈希覆盖候选内容、语义哈希、冻结上下文哈希和
   全部候选级评估证据引用。
3. 要求 `technical`、`development`、`selection`、`full`、`holdout` 证据均存在且
   通过，轨迹完整后才能审批。
4. 在 `MiningV2Store` 增加资格读取、证据哈希、审批记录、当前有效性和最终审批接口。
5. 审批写入在数据库锁和事务内完成审批插入、候选 CAS 状态迁移、事件和轨迹追加；
   相同请求幂等，冲突请求拒绝。
6. 更新桥接文档、包导出、根进度和 AiRecord 记录。

## 验收

1. 满足审核条件的候选可批准或拒绝，重复相同决定幂等。
2. 候选内容、上下文或任一必需阶段证据变化后，旧审批证据不再有效。
3. 缺少或失败的必需阶段不能进入审批。
4. 并发批准和拒绝只能产生一个最终结果。
5. 审批后的 V2 轨迹仍完整可校验，审批记录重新打开数据库后仍可读取。
6. 运行状态保持 `review_ready`，V1 发布链路、Web API 和正式因子不变。
7. 定向单元测试、相关 V2 回归测试、编译检查和 `git diff --check` 通过。

## 边界

- 不实现 P0-03 的发布服务适配。
- 不新增 P0-04 的 API 和页面。
- 不调用 Worker，不执行真实搜索、发布或数据迁移。
- 不提交用户已有的 `TODO_docs/` 文件移动。
