# 20261101-7 计划：建立沙箱结构化代码反馈

- 日期：2026-11-01
- 版本：V142
- 类型：feat
- 进度任务：P1-01

## 目标

为 M5 代码研究循环建立稳定、可脱敏、可持久化的结构化失败反馈，使编译、运行、
输出格式、日期或股票索引、覆盖率、数值、代码限制和资源问题具有唯一错误分类。
完成 P1-01 后停止在本轮，不提前实现 P1-02 的确定性评估器。

## 实现

### P1-01.1 反馈契约

- 新增 `mining_sandbox.feedback`，定义不可变反馈对象、分类枚举、固定错误码映射、
  严格序列化和稳定哈希。
- 固定错误码 `MINING-138`～`MINING-145`，分别对应编译、运行、输出格式、索引、
  覆盖率、数值、代码限制和资源限制。
- 提供 `SandboxFeedbackError`，允许后续确定性评估器携带结构化反馈向上反馈。

### P1-01.2 脱敏和日志

- 反馈文本移除已知密钥、常见 API Key、Bearer Token 和宿主机绝对路径，并限制长度。
- 新增沙箱事件日志入口，只记录运行、轮次、代码哈希、错误码、分类、阶段、可重试性
  和反馈哈希，不记录原始代码、研究假设、完整 stderr 或 Prompt。

### P1-01.3 研究循环接入

- 对每轮提案执行安全的静态编译检查；语法失败记为 `MINING-138`。
- 容器超时记为 `MINING-145`，非零退出记为 `MINING-139`。
- 指标文件读取和校验区分 `MINING-140`～`MINING-143`。
- 新尝试同时保存原 `error_code` 和脱敏 `feedback`；旧运行中缺少该字段的记录仍可恢复。

### P1-01.4 记录与提交

- 更新沙箱专题、项目导向、根进度、版本、变更、差异和进度文档。
- 只暂存本轮相关文件，不提交用户已有的 `TODO_docs/` 文件移动。
- 验证通过后直接提交 `feat(mining): structure sandbox code feedback`。

## 接口

- 新增 `SandboxCodeFeedback`、`SandboxFailureCategory`、`SandboxFeedbackStage`、
  `SandboxFeedbackError` 和反馈脱敏/日志函数。
- 沙箱尝试记录新增可选 `feedback` 字段，原 `error_code` 和 `status` 保持兼容。
- 不修改 Worker v4 请求协议、数据库结构、HTTP API、V1/V2 搜索状态机或发布链路。

## 测试

1. 分类与错误码映射唯一，反馈严格解析、稳定哈希和非法字段拒绝。
2. 路径、密钥、Token、自定义密钥和超长反馈被脱敏；事件日志不包含原始代码。
3. 编译、运行、超时、输出格式、索引、覆盖率和数值失败分别产生正确错误码与反馈。
4. 新旧运行状态兼容，既有沙箱、Worker 协议和产物封存测试不回归。
5. Python 编译检查、`git diff --check` 和项目布局检查。

## 边界

- 不实现交易日/股票索引、覆盖率、非有限值和代码限制的完整确定性评估，这些属于 P1-02。
- 不调用真实付费 Worker，不访问生产正式因子目录，不改变 V2 和 M5 默认关闭策略。
