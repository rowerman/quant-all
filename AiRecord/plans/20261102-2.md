# 20261102-2 P3-02 自由探索初始方向

## 目标

完成 `FACTOR_MINING_PROGRESS.md` 的 P3-02：在没有用户初始假设时，根据冻结字段目录生成
一个可审计的首轮研究方向，并接入现有 V2 搜索和 Worker 候选生成链路。

## 范围

- 为 `SearchRunRequest` 增加仅用于自由探索的可选 64 位随机种子。
- 定义机制类别、数据依赖、表达复杂度和生成依据稳定的 `ResearchDirection` 契约。
- 使用固定、版本化的机制配置和可复现随机选择生成首轮方向。
- 在 V2 首次调用 Worker 前持久化方向和种子，恢复时复用已保存结果。
- 保持手工假设请求、现有 Worker 协议、V1 和 Web/API 行为不变。
- 不实现 P3-03 的方向池、多样性、语义去重和连续无改善停止。

## 接口设计

1. 手工假设模式不参与随机种子，显式提供种子时拒绝请求。
2. 自由探索未提供种子时，从请求哈希前 16 位派生 64 位种子。
3. 显式种子进入自由探索请求哈希；未提供种子时保持 P3-01 哈希算法。
4. `ResearchDirection` 记录请求、上下文、profile 和方向内容哈希，并派生稳定方向 ID。
5. 首轮方向通过 `free_exploration_direction_planned` 事件和初始假设 metadata 双重保存。
6. 方向不可生成时使用新错误码 `MINING-161`，不静默退化为空假设。

## 实施步骤

1. 扩展请求契约、公共导出和错误定义。
2. 新增方向契约、固定机制配置和确定性生成模块。
3. 修改 V2 搜索首轮初始化与 Worker 深度选择，保留原手工假设路径。
4. 增加契约、生成器、恢复、编排、存储和 API 兼容测试。
5. 更新挖掘文档、根进度、版本、变更和差异记录。
6. 运行定向测试、编译和差异检查，只提交本轮文件。

## 验收

- 同一请求、上下文和种子生成完全相同方向和方向哈希。
- 八个机制类别均有可用的冻结字段映射，方向记录数据依赖和复杂度。
- 自由探索首轮 Worker 请求带有效假设和方向声明的最大表达式深度。
- 恢复不重新生成方向；手工假设请求和旧自由探索字典保持兼容。
- 方向、事件和 Worker 请求不包含选择期、最终研究期或测试段正文。
- 不调用真实付费 Worker，不修改正式因子、候选审批或发布数据。
