# 20261102-9 P4-04：V1/V2 到 V3 的显式迁移与兼容

- 日期：2026-11-02
- 版本：V160
- 类型：feat
- 进度任务：P4-04

## 目标

在不修改 V1/V2 原表的前提下，通过显式命令把旧运行、上下文和候选复制为
`mining_v3` 中的只读快照，并提供可重入迁移、受限回滚、中断恢复和旧运行读取入口。
本轮不实现 V3 运行编排或页面；这些属于 P4-05。

## 需求拆分

1. V160-1：为 `mining_v3` 增加迁移来源、legacy 上下文、运行和候选表。
2. V160-2：分别读取 V1、V2 的稳定快照，拒绝活动运行和未知 schema 版本。
3. V160-3：在单一事务内创建 V3 schema、复制旧快照并记录迁移完成状态。
4. V160-4：实现重复迁移的幂等复用和迁移后源数据漂移检测。
5. V160-5：提供旧运行、上下文和候选的只读兼容查询。
6. V160-6：实现仅在 V3 无业务写入时允许的事务化回滚。
7. V160-7：提供脱敏的 `migrate`、`status`、`rollback` CLI。
8. V160-8：完成定向测试、文档、进度、版本、变更、差异和独立提交。

## 设计边界

- 普通 `MiningV3Store` 初始化继续拒绝已有 V1/V2 库，不隐式迁移。
- V1 和 V2 表保持原样；V3 只复制支持旧运行只读展示所需的摘要事实。
- 迁移完成状态最后写入，失败或中断时整个 `mining_v3` schema 回滚。
- V3 出现任何业务写入后禁止执行迁移回滚。
- 本轮不迁移正式因子、缓存或大体积评估产物。

## 验证

- 使用临时 DuckDB 覆盖 V1-only、V2-only、V1+V2、幂等、源漂移和活动运行。
- 注入复制失败，验证 schema 回滚和后续重试。
- 覆盖受限回滚、写入后拒绝回滚、legacy 只读读取和 CLI 脱敏输出。
- 运行 V2/V3 存储、项目布局定向回归以及 `compileall`。
