# 2026-11-02 V163：持久化 V3 运行恢复状态

完成 P5-01。V3 不再依赖进程内字典保存请求、输入、冻结上下文和 CoSTEER 预置候选；
服务重启后可从 `mining_v3` 与 `mining_v3.runtime_*` 重建并校验运行状态。

## 主要变更

- 新增 `V3RunExecutionState`，统一承载请求、上下文、输入包络、资料输入和 CoSTEER
  预置候选。
- 新增 `mining_v3.runtime_seed_candidate`，在创建 CoSTEER 运行前幂等保存人工转写候选；
  已记录候选的旧运行可从 V3 候选包络回退恢复。
- V3 创建运行前持久化输入和上下文；候选同步、搜索编排和恢复不再读取进程内运行字典。
- `resume()` 在状态迁移前重验运行身份、请求哈希、预算、模型配置、上下文、输入、
  资料摘要、预置候选、全部候选证据和既有审批。冲突返回 `MINING-165`，运行状态不变。
- V3 服务启动会把遗留 `queued` 和活动阶段标为 `interrupted`，显式恢复回原状态；
  V2 启动只接管原活动阶段，队列态行为保持原样。
- 新增手工假设、自由探索、资料驱动、CoSTEER 四类来源重启测试，并补充上下文、候选
  证据、审批证据和 CoSTEER 种子篡改拒绝测试。
- 按用户确认，把既有 V162 文档更新和两个 TODO 文件移动并入同一提交；用户已有的
  `.gitignore` 改动继续保留在工作区，不进入本提交。
