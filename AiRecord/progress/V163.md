# V163：持久化 V3 运行恢复状态

## 目标

按 `FACTOR_MINING_PROGRESS.md` 的优先级实施 P5-01，使手工假设、自由探索、资料驱动和
CoSTEER 四类 V3 运行在服务重启后可从持久化事实恢复，且不重复已完成付费步骤。

## 需求明细

- V163-1：持久化 V3 执行所需请求、输入、上下文、资料输入和 CoSTEER 预置候选。
- V163-2：关闭服务并重建存储后可从 `mining_v3` 与 `mining_v3.runtime_*` 重建运行。
- V163-3：恢复前重验输入、上下文、来源、候选包络和既有审批，不接受客户端补交状态。
- V163-4：启动时接管遗留 `queued` 运行，显式恢复后返回原状态。
- V163-5：增加四类来源恢复、篡改拒绝和 V2 兼容测试。

## 实施状态

已完成。

## 实现结果

- V163-1 已完成：新增 `V3RunExecutionState` 和
  `mining_v3.runtime_seed_candidate`。请求、冻结上下文、输入包络、资料输入和
  CoSTEER 预置候选均从持久化事实读取，创建与候选同步不再依赖进程内字典。
- V163-2 已完成：重开 `MiningV3RuntimeStore` 后可恢复四类来源运行。恢复沿用已完成
  Worker 轮次和资料摘要，不重新执行已成功的付费步骤。
- V163-3 已完成：恢复前核对运行身份、请求哈希、预算、模型配置、上下文、输入、资料
  输入、CoSTEER 种子、候选包络和既有审批。失败返回 `MINING-165`，中断状态不变。
- V163-4 已完成：V3 服务启动调用 `interrupt_orphaned_search_runs()`，接管遗留
  `queued` 和活动阶段；显式恢复只回到原状态。V2 启动仍只接管原活动阶段。
- V163-5 已完成：新增 `tests/test_mining_v3_recovery.py`，覆盖四类来源重启、篡改
  拒绝、CoSTEER 队列态和审批证据校验。
