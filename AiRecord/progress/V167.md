# V167：定位正式发布测试的间歇性键集差异

## 目标

按 `FACTOR_MINING_PROGRESS.md` 实施 P5-05，定位正式发布全量测试中的键集差异和
`analysis_tools` schema 歧义，保证正式发布稳定且失败时不破坏旧因子。

## 需求明细

- V167-1：重复隔离全历史发布并收集失败现场。
- V167-2：修复 DuckDB catalog 与 schema 同名导致的初始化失败。
- V167-3：定位全历史查询中的键损坏。
- V167-4：将因子值和正式键集分离生成。
- V167-5：替换不稳定的重型键集校验。
- V167-6：完成全量和定向验收。

## 实施状态

已完成。

## 实现结果

- 分析工具测试数据库由 `mining.duckdb` 改为 `factor_mining.duckdb`。
- 发布查询增加稳定 `row_id`；正式因子值按 `row_id` 计算，最终分区从直接扫描行情库
  生成的受信键集回填股票代码和日期。
- 键集校验改为行数加 `bit_xor(hash(stock_code, trade_date))` 签名，避免双向
  `EXCEPT ALL` 聚合和重反连接。
- 新增小数据正反例单测，并保留既有提交失败旧因子不变测试。
- 唯一全历史发布用例在独立 pytest 子进程执行，避免长进程内的 DuckDB 原生状态污染。
